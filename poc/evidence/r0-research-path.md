## 合理推断（未开库，不得写成已通过）

1. 企微外部群在个微库中的内部键，历史资料常见 `@openim` 一类标识；附件导出器会丢掉这类会话。PoC 已把该排除当作反例，而不是策略。实际键必须在授权开库后的受限定位里确认。
2. 目录名 `wxid_example_account_dir` 与消息表 `Name2Id.user_name` 不一定相同；`示例本人` 只是 UI 显示名，不能当 `self_sender_key`。
3. 当前 `live_read_blockers` 在开库前就要求 `group.conversation_key`。这与 spec §3.2「内部标识未知时允许 R0 受限定位」不一致：没有内部键就无法开库，没有开库就得不到内部键。这是 **适配缺口**，不是密钥研究问题。

## 允许继续的研究途径

在操作人把已有密钥放到环境变量、并显式 `allow_live_read=true` 之后，R0 应按下面顺序做，且每步失败即停：

1. **只读打开测试账号的 `message_0.db`（SQLCipher）**
   只证明：指定文件可被授权密钥打开。不遍历正文。密钥材料范围可能大于单群，程序仍只能查白名单会话和身份映射。
2. **受限定位（元数据，不是全历史导入）**
   用已记录的显示名 `示例混合群` 与六条成员特征（含两个「示例群主」必须带企业前缀）匹配会话/联系人元数据。匹配 0 或 >1：停止，不填猜测键。匹配恰好 1：写入 `conversation_key`。
3. **身份映射**
   将 UI「微信联系人/示例本人」对到 `Name2Id` 中的 `self_sender_key`；对不上则 `is_self=unknown`，不得派生发送任务。
4. **基线**
   首次只存 `local_id`/`create_time` 元数据，不导入历史正文。其后才谈 R1 合成探针。

在密钥未提供前，研究只停留在上述契约、离线测试和 UI 线索，不进入第 1 步。

## 不是研究步骤

- 运行附件取钥/解密/导出
- 为「找群」扫描全部会话正文或全部 `Msg_*` 表内容
- 用群名、`@openim` 或第一个会话填 `conversation_key`
- 把附件随包 `decrypted/*.db` 或 CSV 当作本测试号的实机证据
- 切换路线 B（桌面读）来填补路线 A 的库可读性

## 代码缺口（密钥到位后才改）

若要让 spec 的「内部键未知时受限定位」可执行，需要把 G-READ 拆成两档，而不是现在的「没有 conversation_key 就拒绝开库」：

| 档 | 允许 | 仍禁止 |
|---|---|---|
| G-READ-locate | 打开指定账号库；只读会话/联系人元数据；按 UI 线索唯一匹配 | 消息正文、非测试账号、附件取钥 |
| G-READ-ingest | 已有唯一 `conversation_key` 后的增量文字读取 | 历史全量导入、跨群 |

未拿到操作人密钥引用前，不实现也不试用这两档的实机路径。
