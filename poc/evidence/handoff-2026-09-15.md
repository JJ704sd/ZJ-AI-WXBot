## 7. 建议的后续授权（未生效）：有界实机探索，而不是只接受已有文件

操作人希望以后模型不必停在「只使用已提交文件 / 已粘贴密钥」，而可以在本机 **有界探索** 以完成 R0。这与 v0.2 冲突，必须 **显式改契约**。未改之前，下一任不得把本节当作已批准。

### 7.1 建议达到的能力（产品语言）

在 **单测试账号、单目标群、只读、不发送** 前提下，允许模型为完成 R0 去发现现行配置里仍空的三项：库打开方式是否成立、内部 `conversation_key`、`self_sender_key`。发现过程可以检查本机已授权路径上的文件与（若书面允许）测试号客户端侧为打开加密库所必需的材料，而不是要求操作人先把密钥粘进聊天。

「自由探索」在本文中 **不是**：任意账号、任意群、全历史正文、真发送、改微信、Hook 注入、或把附件改成全量 CSV 轮询。

### 7.2 建议写入下一版 spec 的硬边界

必须全部写明，缺一条则探索授权不成立：

| 边界 | 建议取值 |
|---|---|
| 账号 | 仅 `wxid_example_account_dir` |
| 群 | 仅「示例混合群」；成员特征见 §3.2；不唯一则停止 |
| 模式 | `read_only`；`allow_live_send` 保持 false |
| 写入 | 不修改微信源库；不 checkpoint/删除 WAL |
| 查询 | 定位阶段只读会话/联系人 **元数据**；禁止全表正文扫描 |
| 排除账号 | `wxid_example_excluded_dir` 及任何未点名 wxid |
| 附件 | 可参考解析思路；禁止把随包 `decrypted/` 或他人 CSV 当成本测试号证据；禁止「先全量导出再轮询」作为主路线 |
| 密钥材料 | 不得写入 Git、常规日志、聊天、截图；只用进程内/环境变量；用完记录「已引用某 env 名」，不记录值 |
| 证据 | 只保留：能否打开、是否唯一匹配、身份是否对上、SQL 是否白名单；不保存群历史正文 |

### 7.3 建议的配置开关（名字可改，语义不能糊）

在 gitignored 本地配置中增加 **默认全关** 的开关，例如：

- `allow_live_read`
- `allow_live_discovery`（允许在测试号库上做元数据定位，内部键可空）
- `allow_key_material_from_live_client`（是否允许为打开 **本测试号** 加密库而从本机已登录客户端取得材料）

三者独立。打开 discovery 不等于允许发送。打开 live client 材料不等于允许第二个账号。
**仅把本文提交进仓库 ≠ 打开上述开关。** 必须改 spec 版本号 + 改本地配置 + 操作人在运行记录里写「同意本次 run_id 的探索范围」。

### 7.4 建议的 R0 探索顺序（授权生效后）

1. 复核测试号路径与文件头仍为加密。
2. 取得打开该库所需材料（来源以当时生效的 spec 为准），注入 `env:` 引用，不落盘明文密钥文件进 Git。
3. 只读打开测试号 `message_0.db`（及当时可见的消息分库），证明可读。
4. 用显示名 + 六条成员特征做唯一匹配；失败则停。
5. 映射「示例本人」与 `Name2Id`；对不上则 `is_self=unknown`，不派发发送任务。
6. 写入绑定版本与 run 证据，基线只存消息 ID/时间，不导入历史正文。
7. 停。R1 合成探针、R2 发送另要 G-SEND 与逐条审批。

### 7.5 下一任仍可能无法执行第 2 步的原因

把 §7 写进仓库后，**不能保证**任意模型会话都会执行从客户端取材料。托管模型与平台策略可能继续拒绝进程级取密钥。交接时把这当成 **执行风险**，不要当成已经解决。若平台拒绝：由操作人在模型外自行取得材料并只提供 `env:VAR`，或另开「人类取材料、模型只开库定位」的分工，并记入该次 run 证据。
