# 桥接注册链补全与前轮漏查纠正

## 确定发现

上轮未找到构造引用，原因之一已明确：探索脚本只保留 `PEImage.function_at` 返回非空的命中。实际构造函数是没有展开表记录的短函数，因此被过滤掉。它使用的仍是上轮扫描支持的 RIP 相对 LEA，并非特殊地址编码。不能把“没有展开表记录”解释为“不是代码”。

这解释的是静态定位漏查，不是 R4 的运行时零命中。原始扫描文件保留，先前报告的零构造引用应理解为过滤后的结果，不能继续用于推断注册关系缺失。

## 已建立的静态关系

1. 含 `mars::stn::SetCallback` 字符串的函数向一个短入口传入管理器及回调参数。
2. 短入口保存回调参数，再尾跳到展开表中可识别的管理器辅助函数。
3. 辅助函数检查桥接对象是否存在；空值分支分配对象并直接调用短构造函数。
4. 短构造函数把此前找到的连续函数指针表写入对象首字段，然后返回。通过直接调用目标定位并从目标开始解码，避免仅凭任意字节猜函数起点。
5. 辅助函数把桥接对象保存到管理器成员，通过表中 SetCallback 槽传递业务回调。
6. 桥接 SetCallback 保存参数的对象成员，与 OnPush/Buf2Resp 桥接读取的成员一致。
7. 管理器 OnPush/Buf2Resp 读取桥接对象的成员与辅助函数写入位置一致，使用的两个虚表槽分别对应已找到的桥接方法。

因此已有“注册代码 → 构造 → 桥接表 → 委托成员 → 间接业务调用”的静态闭环。具体业务回调参数来自哪里、运行时注册了哪个实例，以及与旧接收候选是否有关系，仍未确定。

## 验证及证据

核查了 SetCallback 字符串引用的完整展开表范围、短入口至尾跳指令、管理器辅助函数完整范围、直接调用指向的短构造函数，以及桥接 SetCallback 的参数保存指令。短构造函数从调用目标至 ret 完整解码；不存在展开表记录的事实单独保留，未伪造函数元数据。

原始证据位于忽略目录：callback-setters.private.json、setter-2.txt、setter-4.txt、manager-registration.txt；构造指令通过本轮 objdump 有界命令实际核对。本轮只读磁盘模块，没有附加进程、读取载荷、注入 DLL 或发送消息。
