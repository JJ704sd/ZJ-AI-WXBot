# 群聊内容补齐 v46 / Skill 1.32.0

## 目标与证据

基于 v45，修复本次 117 群归档审计发现的媒体漏扫、消息类型适配、引用来源关联及内容完整性说明缺口。保留既有原始数据、人工复核、指定目录和可恢复发布流程；不重新采集真实账号，不改写已有导出。

引用标识的只读抽样验证：160,223 条记录、48,227 个引用中，23,517 个引用的 entry.16 与同群源消息 extra.3045.3.3、发言人、时间唯一匹配，其中 21,799 个嵌入正文摘要一致。不能把 entry.16 当 server_id。适配须保留同群、发言人、时间、已知类型与已有正文摘要校验；多候选不关联。

同一抽样中，在 entry.16 缺失时读取 envelope.2，唯一的来源键、发言人和时间匹配增加到 46,204 处，其中 40,926 处有相同嵌入正文摘要。适配只在信封、发送者与时间结构有效时读取该备用位置，存在多个标识值时不选择其中一个。

## 实现契约

1. 企微媒体摘要检索取消 512 MiB 总预算，遍历所选账号 Cache 内全部符合单文件上限的文件，不能被前 50,000 条快速索引截断。使用临时磁盘 SQLite 摘要索引，跨群复用未变文件，每次导出重新核查文件状态，新建、修改、删除均可见。最终拷贝仍核对摘要。读取失败、超限、变化须统计，检索未完整时不宣称本地没有原件。扫描进度持续反馈。单文件 100 MiB 上限保留并明确记录，不因取消总预算扩大内存占用。
2. 增加已观察到的企微 101 图片、102 文件元数据适配，格式不符仍保留未适配状态；不得把链接凭据或任意 protobuf 字符串当正文。补充缺少类型的引用信封读取和实际来源键索引，保留旧来源标识兼容。
3. 缺口清单覆盖主消息、引用与嵌套转发，必须在引用恢复及附件正文提取后生成。记录消息证据、节点位置、媒体摘要、文件状态、正文状态及可操作后续步骤，不把引用内文件遗漏。
4. 完成页明确区分记录发布、原件取得、正文提取及来源关联。保留原有统计契约，添加补齐清单与引用覆盖率；无匹配不是原消息不存在，无正文不自动等于空白或 OCR 成功。
5. 未缓存原件需用户在原客户端打开或下载；扫描件需后续 OCR；加密文件需合法密码或解密后的副本。首版不新增联网下载、外部模型、OCR 依赖或密码破解。未知格式继续保留原始字段并进入补齐清单。

## 验收

合成回归验证晚序文件、跨群摘要复用、源文件变更、路径边界、错误完整性状态、引用缺少类型/冲突/循环、引用与转发缺口、附件补齐建议。对授权归档只读重解析并输出汇总差异，不输出真实正文或身份；区分解析改善和实际缓存取件成功。完成相关既有群聊/私聊兼容检查和 Windows EXE 合成验证，交付全新 v46 包，历史 ZIP 摘要不变。
