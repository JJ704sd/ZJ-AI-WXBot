# 群聊自动正文解析增强 v48

目标：减少附件已取得但关键正文未进入分析材料的漏项。沿用 v47 的原件校验、当前账号配置、密码和人工复核流程，不更改历史交付。

## 实施计划与完成判据

1. 用合成材料复现图片附件、混合 PDF、Office 内嵌图片和多页 TIFF 的漏项。
2. 在原件 SHA-256 校验后识别格式；已启用文档 OCR 时自动处理图片附件。PDF 对有位图的页面也补充 OCR，保留原生文字。Office 仅识别实际引用的内嵌图片，标明文档部分、工作表或幻灯片；忽略外链和未引用媒体。
3. 本机 OCR 支持多页 TIFF；保留行结构及识别图像像素坐标，不将 OCR 自动解释成可靠表格或业务结论。单个图片或页失败时保留其他结果，缺口显式标出。
4. 执行针对性回归、原有核心与 GUI 检查、双客户端打包 EXE 合成导出验证，保留旧包并更新交付索引。

## 兼容与资源约束

- `ocrEnabled` 扩展为文档 OCR（图片附件、PDF 扫描内容、Office 内嵌图片）；`ocrImages` 继续控制聊天原图，默认仍关闭。设置文案说明覆盖范围。
- `attachmentContent` 保持 schemaVersion 1；新增格式来源和 OCR 定位字段，不删除现有字段。正文进入既有阅读、搜索、分析和完整性统计链路。
- 每文件 20 MiB、Office 展开 40 MiB/5000 条目、至多 100 页/内嵌图片、正文 200000 字符；触顶和识别失败不标为完整。
- 不抓取外部链接，不猜密码，不把缩略图或预览当原件。不声称能够恢复客户端和备份中都没有的原件。
- Windows OCR 在本机运行；数字、单位、表格关系必须结合原件复核。合成验证不代表真实账号恢复率。
