# 群聊 v49：缺口核查与原件补齐

目标：针对117群旧导出的媒体与附件缺口，修复仍可复现的漏检和正文损失，减少重复补文件操作。保留原件校验、账号边界及人工复核，取消与正确性无关的默认检索配额。

## 已核查的痛点与方案

| 痛点 | 处理 |
| --- | --- |
| 旧截图的解码率被误当成当前内容完整率 | 区分旧包统计、v46以后新增消息适配及当前原件/OCR覆盖；不把合成测试当真实恢复率 |
| 个微内容兜底仍默认截断于20000文件/2GiB，单文件100MiB；每群重建重读 | 默认扫描完整所选账号媒体目录，普通文件流式哈希并复用未变化文件结果；显式调用方预算仍可用 |
| 双端已缓存的大附件因100MiB限制被跳过 | 桌面导出采用流式校验和落盘，取消普通原件大小阈值；解码容器和正文提取资源上限分别保留并说明 |
| 本地预览和缩略图有可读文字却不OCR | 已开启图片OCR时允许识别已校验的可用预览，明确预览来源、部分正文与待复核；原件统计不升级 |
| 缺口按每条引用列出，重复下载同一件 | 生成按原件MD5归并的待补清单，附件优先，保留引用次数、群/消息定位和时间；无摘要不按同名合并 |
| 原件未在缓存/补充目录、密码未知、消息类型未适配 | 保留为具体未解决缺口；不把原始字段拼成可靠正文，不冒充已下载原件 |

## 当前计划与完成判据

1. 通过合成用例复现扫描限制、大附件和预览OCR漏项。
2. 实现流式原件落盘、个微完整兜底与跨群缓存、预览OCR及按原件归并的清单，接入现有界面。
3. 只读复核旧ZIP，生成实际缺口优先清单与聚合证据，不修改原ZIP和源数据库。
4. 定向测试、原生界面与双客户端最终EXE验证通过后发布 v49 / Skill 1.35.0，保留35个历史ZIP。

本轮不新增通用重试层、审批步骤或网络协议猜测；只保留可读性、内容完整性和账号归属所需校验。在线原件下载需有效且受支持的客户端授权协议，消息中的不透明下载地址不等于可用原件。

## 执行结果

四步均已完成。160项核心、32项GUI检查通过；最终媒体6项复验通过（与核心项重叠）。最终个微、企微EXE实际完成101MiB原件导出、预览OCR及缺口去重清单，原图缺失状态未被升级。

只读核查117群旧包：20,399处引用归并为12,878项补齐任务；1,020份去重图片预览实际OCR得到775份文字，245份未识别到文字，源ZIP未变。真实增补材料仅保留在本机outputs，交付包中不携带聊天和图片。
