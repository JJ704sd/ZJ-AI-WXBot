# 群聊原件、OCR 与密码补齐 v47

目标：在 v46 上补充可实际执行的本地恢复路径，保留原件与提取结果的区别。两种客户端共用处理模块，既有导出及私聊安装包保持不变。

1. 用户选择补充目录；仅用消息声明的原件 MD5 精确匹配。文件名不作身份依据，不将缩略图当原件。不自动联网下载；客户端未缓存的文件须先下载或由用户提供副本。
2. Windows 本机 OCR 按需处理 PDF 无文字页及图片，保留页号、引擎、语言与人工核对标志。单文件超时保留已识别页，后续文件继续；已有可提取的 PDF 文字优先保留。
3. PDF 和现代 Office 附件支持用户提供的打开密码。只尝试对应文件 SHA-256 绑定的密码；不猜测密码。桌面输入的密码只在当前账号会话内使用；可选密码 JSON 文件只保存路径，内容不进入导出、诊断和命令行。
4. 设置是现有 source 配置的可选字段：supplementRoot、documentPasswordFile、ocrEnabled、ocrImages。缺省均关闭，旧配置可读取。跨账号不得继承补齐设置及会话密码。改变设置后重新解析生效，原有待复核结果及正式导出保留。
5. 补齐清单增加文件 SHA-256 和对应行动；OCR 文字始终标为待核对。报告新增补充目录检索统计，保留缺口和失败原因。

验收：合成文件覆盖精确匹配/同名异内容/改变源文件、PDF/图片本机 OCR、混合 PDF、正确/错误/缺失密码、超时部分结果、旧配置兼容与账号隔离；编译程序验证两客户端导出及凭据不泄露；历史交付包摘要保持一致。

新增依赖：msoffcrypto-tool==6.0.0（MIT），用于读取用户提供密码的 Office 加密容器。OCR 使用 Windows 自带组件；本机无 OCR 语言时明确标记不可用，保留原文件。正文仍受单文件大小/页数/字符数限制，超过范围明确报告。

密码 JSON 可选格式：`{"schemaVersion":1,"passwords":{"文件的64位SHA256":"已知打开密码"}}`。留空表示尚未提供。密码文件由用户保管，不应与导出材料一起分享。


完整性概览：解析后主界面显示当前群的记录、原件/引用、正文/引用及待补齐或核对数量；点击“完整性概览”切换当前群/所选群，查看未解析、复核及正式导出进度，并按图片、附件、正文、OCR、密码、引用来源区分覆盖。大数在概览卡片作万位简写，表格保留精确值。预览不计原件，旧版缺少统计显示待核查；不把导出进度当内容完整率。
