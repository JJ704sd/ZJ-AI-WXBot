# 私聊分析助手 1.6：宿主分析与桌面复核衔接

基线为已验证的 1.5.0。保持宿主模型分析、脚本校验、本地持续存储、人工确认入库及跨端身份人工关联的既定边界。

## 痛点与结果

现有材料窗口只能复制文件路径，桌面候选入口只能读取画像库中已经暂存的文件。宿主输出的普通 JSON 无法直接进入桌面复核，用户需要理解并执行 ProfileStage 命令。

本轮提供完整的桌面路径：准备已复核材料 → 复制可直接交给宿主的分析任务 → 导入宿主候选 JSON → 校验原消息与身份 → 打开现有人工复核窗口。导入只暂存候选，关闭或取消复核不形成正式画像。

## 行为契约

- 材料窗口增加“复制分析任务”，包含请求及材料路径、当前画像路径、固定请求标识、基线版本、分段覆盖要求、候选字段规则和有效 JSON 示例。任务文本不包含聊天正文，也不直接调用模型。所有路径和身份来自已准备的请求。
- 已确认材料没有增量时不生成新候选，窗口仍可复制路径；说明无需重复分析。
- 桌面新增“导入宿主候选…”菜单；现有第三个私聊快捷按钮改为导入并复核。原有画像库候选复核入口继续保留在菜单中。
- 导入服务使用现有 4 MiB JSON 读取、链接路径拒绝与 ProfileStore 校验。先验证当前正式导出，再核对请求的 client、accountKey、peerId；不一致时不得暂存。
- 从材料窗口进入时额外绑定该窗口的 requestId，防止不同批次混用。窗口对应的客户端或导出选择已改变时拒绝操作，提示返回该材料会话。普通菜单导入允许同一身份的其他批次，原请求材料仍必须有效且基线未过期；复核窗口显示真实来源和范围。
- 文件选择框会启动嵌套事件循环，因此选择前后均核对忙碌、关闭及会话上下文。取消、错选、读取失败和校验失败不入正式库，并可修正后重试。
- 重复导入同一有效候选复用现有 candidateId；不覆盖宿主原文件。已确认候选保持原有幂等行为。
- 不改变持久化 schema、历史请求 ID、CLI 命令或原群聊入口；不新增生产依赖。

## 分工与当前计划

1. 主 Agent：本 spec、导入服务 helper、整合、版本和分发验证。
2. 材料界面子 Agent：private_insights_ui.py 的分析任务生成与窗口按钮，以及独立回归。
3. 桌面子 Agent：local_chat_app.py 的导入入口、上下文检查和人工复核衔接，以及独立回归。
4. 服务验证子 Agent：使用真实 ProfileStore 和合成导出测试导入成功、身份不匹配、错误 JSON、过期基线、重复导入与不自动确认。
