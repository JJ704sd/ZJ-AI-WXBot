# 私聊分析助手 1.7：界面层次与导出恢复

基线 1.6.0。用户本轮明确要求继续改善 UI，并防止导出中断导致已完成工作丢失。保持 Windows 原生便携入口、宿主分析、人工确认、本地画像与既有数据格式；旧版交付全部保留。

## 设计方向

沿用已建立的浅色、绿色重点和内容卡片风格，参考此前已查看的 WeChatDataAnalysis 设计思路，独立实现。优先改善层次和可操作性，不新增浏览器运行时或生产依赖。

- 私聊主页：把解析、复核导出、画像分析的先后顺序与当前状态说清；主操作有明确视觉重点，次要 ID 和设置降低干扰。已保存信息始终可查。
- 聊天统计：减少嵌套导航和横向拥挤，突出数字含义、范围与趋势；保留现有统计、检索、日历及回顾行为，空结果有下一步提示。
- 画像复核：标题、主体、观察内容、证据出处分层展示，避免整屏等权文字；新旧/待确认与已确认状态明确。确认项仍默认未选。
- 常规及较小窗口下保留主要操作和阅读面积；长名称、长状态、空数据、长正文都纳入实际 Tk 检查。视觉预览须注明是原生截图还是根据实际控件生成的布局图，不混淆。

## 导出可靠性边界

首先复现现有 prepare/confirm/export_reviewed 在写入失败、重试和新进程恢复时的实际缺口，再补充最小必要机制。已有正式导出不得被覆盖或当作失败清理；尚未完整落盘的数据不得显示为成功。

恢复状态必须绑定所选客户端、账号、联系人、日期、复核材料摘要和明确的用户复核结果。恢复不得擅自更换数据源、跳过人工复核或把不完整临时文件作为正式导出。单个会话失败不能使其他已完成会话丢失。

在改动持久化恢复契约前，由主 Agent 将具体字段、写入顺序与重试语义补充到本 spec。

### 已复现问题及确定的恢复契约

1. prepare_review 在开始解析前 discard 旧状态，失败后已复核状态丢失。改为先生成新缓存和视图，校验并原子保存新的 checkpoint 成功后，才替换内存中的旧复核、视图与已导出状态。解析或保存 checkpoint 失败时保留旧版；不得删除旧正式导出。
2. 已完成导出在 checkpoint 中消失，重启仅能恢复未导出的会话。保留已发布会话的恢复项，复用现有 v1 entry 的 root、summary、files、approval、exportTarget 字段，不修改正式导出格式。保存时包含待复核与已发布项；恢复时分别返回待处理项与已发布项。已发布项必须重新核对来源绑定、人工复核、manifest 文件清单、每项大小与摘要，不能仅因 exportTarget 存在就认定完成。
3. batch.json 或导出清单.md 写失败不应抹去正文导出成功的事实。清单逐文件用临时文件、flush/fsync、os.replace 原子替换；调用方收到 exports/failed 原有字段及 metadataErrors，而非笼统异常。state 为 partial，metadataComplete 为 False；已完成文件保持原样。所有成功时 metadataErrors 为空、metadataComplete 为 True。
4. 新增 repair_export_metadata(batch_root) 供桌面显式重建清单。仅允许当前来源下 checkpoint 已验证的已发布结果所在批次，重建可用已完成项，不能扫描任意目录推断人工确认，也不能重新导出或覆盖会话正文。返回实际清单结果与剩余缺口。重启后保留批次路径，桌面显示“修复导出清单”入口；失败会话继续通过原导出入口重试。

这是会话级恢复：中断后保留已完成会话与已复核缓存，重新执行未完成会话的文件复制；不宣称断电硬件持久性或单个大文件字节级断点续传。

## 整合补充

桌面队列的 parse_next 与 parse_failed 同样保留已有解析结果及复核状态，待 prepare_review 成功才替换；桌面故障用例先复现“未解析”错误状态，再验证修复后旧结果可读且重启恢复。清单修复保留当前批次尚未完成会话，metadataComplete 仅表示清单写入完整，不能替代会话全部完成。

Windows 画像库锁持有者检测改用 OpenProcess(SYNCHRONIZE) 和零等待的 WaitForSingleObject；查询失败且非明确进程不存在时保守视为仍占用。Windows 不调用 os.kill(pid, 0)，避免 0 对应 CTRL_C_EVENT 导致共享控制台异步中断。来源：[Python os.kill](https://docs.python.org/3.14/library/os.html#os.kill)、[Microsoft WaitForSingleObject](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject)。正式 EXE 增加“陈旧时间戳但持有者仍存活”的合成锁验证，必须超时拒绝并保留原锁，不能发送控制台信号。
