# 私聊分析助手 1.4：从基本约束出发优化

基线：1.3.0。目标是提高正确性、兼容性与失败恢复能力。保留既有用户决策、人工确认流程和本地执行范围。

## 必须成立的约束

1. 身份有依据：客户端、所选账号、会话和消息发送者相互一致；未知不能变成确定归因。
2. 证据可重现：同一份已确认材料不会因为展示或派生字段的计算更新而失效；冲突元数据不得被悄悄选择其一。
3. 增量有顺序：同一条消息的最新已确认内容决定重叠/变化判断，不能由随机摘要排序决定；重复操作不制造新版本。
4. 失败可恢复：成功意味着完整产物已发布；写入失败保留旧状态，重试不受半成品阻碍。
5. 成本有边界：只计算当前操作需要的信息；性能调整必须先有可复现证据，不新增抽象或依赖来猜测未来需求。

## 分工与验收

先以合成数据验证不变量，再实施有失败证据的修复。主 Agent 负责身份与链路整合检查、规格更新、回归与交付；存储 Agent 负责历史兼容和增量顺序；会话 Agent 负责私聊判定及发送者映射；统计 Agent 负责报告完整发布和失败恢复。修改范围互不重叠，涉及共享文件先报告再整合。

公开服务接口、双端实际导出、旧版本已保存材料以及失败后重试是主要验证边界。保留既有 ZIP 和用户数据，不读取真实私聊，不新增模型 API、自动确认或外发动作。

最终交付必须列明实际复现的问题、修复前后证据、回归范围、双端包验证和未覆盖情况。

## 已确认的实现决策

- sourceIds 继续保持唯一来源列表。本次确认的来源移到末尾，重叠消息按最后确认内容比较；完整确认历史保存在版本链中，不重复累积来源 ID。
- 兼容 1.0–1.2 的分析消息时间范围和 1.3 的完整消息时间范围，必须精确等于原记录计算值。旧请求、候选 ID 和文件不重写；消息、身份、分段及摘要检查仍严格执行。
- 源消息 ID 只接受有效文本或非零整数；规范化后查重。拒绝布尔引用，避免 `true` 被语言运行时当作引用 `1`。
- 类型信息存在群聊/私聊冲突时不进入私聊；系统类型判断忽略大小写和首尾空格。
- 报告写入故障注入验证已有清理与重试逻辑有效，本轮保留实现并补充回归，不进行无依据重构。
