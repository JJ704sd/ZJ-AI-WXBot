# 群聊大数据采集与恢复 v44

日期：2026-10-23。基线：v43 / 群聊 Skill 1.29.0。目标交付：v44 / 1.30.0。

## 目标与边界

面向个微、企微的大规模群聊记录，降低处理过程的重复 I/O 和峰值内存，改善长任务反馈以及中断后的继续处理。成功的含义是选定范围内的记录、原始依据、引用关系与异常标记能够完整进入可复核材料，并按用户确认的版本导出；不能以忽略坏记录、跳过密码验证或默默缩小范围换取速度。

继续保留 v43 对明文/加密混合库、企微分库密钥、无效元数据的支持，以及 v42 的逐群发布、断点复用与导出恢复。解密仍执行完整页校验、WAL 和 SQLite 一致性检查；这轮只对已证实的瓶颈动手，不增加无依据的密钥猜测或绕过校验。

## 已确认问题

1. 选中两群、完成第一群后退出，恢复时把选择过滤成已经完成的结果，仍在当前源中的第二群丢失勾选。
2. 后台解析每一群都会立刻构建整份 JSONL 阅读索引，即使用户没有打开这群；1 万条合成记录中约 0.18 秒和全量索引内存用于这一步。
3. 单群解析只展示群序号，处理数千或数十万条期间看不到条数和阶段变化。
4. 企微引用查找缓存本群消息的完整源行，包括正文和二进制内容；个微引用逐次打开数据库并查 schema，需测量后选择本轮最小调整。
5. 企微及个微语音库在嵌套读取调用中重复计算完整文件摘要，随数据大小与引用数量放大耗时。

## 实施约定

- 恢复选择按当前源有效群 ID 校验，独立恢复并校验复核/导出状态。选择恢复本身不代表记录已经复核。
- 第一群尚未完成时也保存有效群选择；无复核结果时不伪造复核记录。首次快照清单摘要在后台加载阶段预热，勾选复用该摘要，避免在 UI 线程扫描大文件。加载事务失败恢复旧缓存与复核状态。
- 为后台解析提供可选的延迟阅读索引路径；默认接口保持兼容。用户打开群时创建阅读视图；已有结果和重新解析失败时的旧视图均须可用。
- 复用现有工作线程事件队列，节流报告已处理条数与处理阶段。不为显示百分比额外扫描全量数据库，不把未确认结果标成成功，不改变“完成当前群后停止”的承诺。
- 引用缓存只保留定位信息和必要匹配标量，按需读取完整记录；保留跨表、重复 token、歧义、时间和内容匹配语义。禁止修改源数据库。
- 完整摘要验证只在明确的顶层读取操作内合并嵌套重复检查；每次独立操作和读取结束仍验证一致性。不得把 stat 相同当成内容永久可信。
- 批量导出和清单修复使用线程隔离的操作校验作用域，开始和结束各执行完整验证，逐群解析的读取前后校验保持不变。退出作用域后不保留可信缓存，异常路径也恢复作用域并执行结束检查。结束检查失败时，批次与清单必须标为部分完成、提示重新加载；已验证并发布的群文件和检查点保留，不回滚或删除。
- 不新增生产依赖，不迁移正式画像或账号格式，不改私聊交付版本。

## 分工与验收

- UI agent：恢复选择、后台视图延迟初始化、群内进度；仅改 desktop/progress/app 及直接回归。
- Runtime agent：引用查询的内存与查询优化；仅改 archive/chat 引用相关路径及直接回归。
- Performance agent：重复一致性检查的操作范围与实测；与 runtime agent 划定代码段，避免重叠。
- 主 agent：整合、实际瓶颈数据、数据完整性检查、版本说明与 Windows 交付。

测试以已复现问题和主要契约为准：两客户端未完成选择恢复、惰性阅读、引用解析等价、源变化检测、导出恢复、记录顺序与数量。使用合成数据测量大群引用与端到端耗时，报告测量范围；不把 SQL 查询局部耗时当成总任务加速。复用现有相关回归，不堆叠与实现同形的防御性测试。

最终检查新 Windows EXE 的解密/解析/复核入口和导出内容，验证归档文件哈希与清单。历史 15 个交付 ZIP 保持不变。真实账号解密成功率、真实业务内容验收、物理断电和其他机器上的表现不作未验证承诺。
