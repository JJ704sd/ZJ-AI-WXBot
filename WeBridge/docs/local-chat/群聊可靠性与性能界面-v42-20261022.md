# 群聊解析与信息分析 v42 / Skill 1.28.0

## 目标和基线

以 Windows 群聊交付 v41 / Skill 1.27.0 为使用基线，继承当前源码中私聊 1.7 已验证的共用导出恢复能力。覆盖个微群聊和企微群聊，不改变私聊入口、画像流程、原账号数据或历史交付包。

用户关心三件事：大量数据处理尽量快；中断后已经完成的工作不丢；界面清楚显示正在做什么、已保存什么和下一步。保留人工复核、身份隔离、消息出处和完整性验证，减少没有业务价值的重复扫描、重复状态和异常吞没。只用合成数据验证，不读取真实聊天或密钥。

## 本轮范围

1. 共用恢复能力进入群聊交付：解析失败保留旧复核，逐群原子发布，完成结果重启恢复，失败群重试跳过已保存群。
2. 批次在第一群发布前记录所有目标。中断后清单必须包含尚未开始/未完成的群，不能把部分正文写成整批完成。
3. 跨群 `batch-analysis` 失败与清单失败均标为部分完成；修复清单同时恢复跨群分析入口，正文不重写。派生文件在暂存区生成后替换，失败不损坏已有分析材料。
4. `DesktopSession.export_reviewed(chats, *, progress=None)` 可选回调报告阶段、已保存数量、总量和当前群；默认调用方式兼容。工作线程仅发送事件，Tk 主线程更新显示，不增加逐文件事件和新任务框架。
5. 群聊界面分为选群、阅读复核、导出分析。整理主次按钮，提供文件菜单、保存路径、修复入口、简洁空状态、完整群资料和长群名展示处理。搜索保留勾选、Enter 仅定位、显式重解析语义不变。
6. 性能先测后改：合成大文件/加密页/多群记录测量耗时和读取量，优先消除同一导出内重复哈希与重复中间处理。不得关闭页 HMAC、WAL 一致性、SQLite 完整性检查或最终正文哈希核对。按实际测量决定解密优化，不能把读取元信息当作内容校验，不新增生产依赖或盲目并行磁盘任务。

## 恢复与兼容约束

- 继续使用既有 v1 复核进度字段，旧进度可读。已有已确认复核才能正式发布。
- 质量状态区分正文保存、派生清单/跨群分析完成；部分成功明确显示，不抛弃可用正文。
- 恢复以群为单位，需要原工作目录、快照与复核缓存。文件移动、来源变化或内容校验失败不能冒充已完成；原正式导出保留。
- 不承诺单个文件字节续传或硬件断电零损失；不添加自动外传、自动清理账号数据或无限重试。
- 重复点击由既有 UI 忙碌边界处理；异常在实际 I/O 边界处理，避免泛化的兜底层。

## 验收

- 两客户端多群部分失败、跨群分析失败、清单失败、首群完成后中断、重启重试、重新解析失败均验证可恢复；旧正文 SHA-256 不变，不重复导出。
- 解析条数、顺序、引用、媒体/附件缺口和导出内容与优化前一致。损坏页/中途变更仍被拒绝。记录同机合成样本的前后性能，不推断真实账号耗时。
- 1000×700 与常用大窗口下，长群名、空状态、完成/失败状态和主要按钮可见；群聊与私聊相关回归通过。
- 执行 runtime identity / SourceBinding 必要检查，构建实际 Windows EXE，两套 Skill 包内版本/绑定/哈希/ZIP 回读验证。
- 交付桌面 v42、两套群聊 Skill 1.28.0、合集及验证说明。v41 和私聊 1.7 包保持不变。

## 分工

- 主 Agent：解密/大数据基准与适当优化、版本和打包文档、集成验证与交付。
