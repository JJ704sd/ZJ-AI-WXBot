# 微信外部混合群 Agent 接入：官方路径核验

核验日期：2026-09-18。目标是让**个人微信账号**参与企业微信创建、同时有微信与企微成员的既有群：持续获取普通群消息、主动发言、真实 @ 两种成员、识别真实 @ 与引用回复并交给 Agent。本报告仅评估官方文档与官方源码；没有登录账号、发送消息或执行下载的软件。

## 结论

本次核验的官方产品中，**没有找到满足全部条件的完整方案**。

| 路径 | 能否覆盖目标既有外部混合群 | 收取普通群消息 | 发言身份及发送能力 | 对目标的结论 |
|---|---|---|---|---|
| 企业微信智能机器人 / `WecomTeam/aibot-node-sdk` | 官方帮助明确：仅内部群；外部群不支持添加 | 群里 @ 机器人等交互触发，不是全量监听 | 企业微信智能机器人身份；支持回复与有前置交互的主动发送 | 明确不适用 |
| 原企业微信群机器人 Webhook，现称“消息推送” | 本次读取的接口页未明确给出外部群开放支持，不能据此确认 | 该接口只有开发者向群推送；没有群普通消息接收回调 | 消息推送机器人身份；支持部分真实 @ 语法 | 即使有可用群，也缺收消息链路 |
| 会话内容存档 | 可以涉及企业员工与外部联系人的会话；须企业开通及满足同意条件 | 获取授权存档范围内的会话记录；不能承诺任意外部群所有人的全量 | 读取/归档产品，没有作为个人微信群成员发送消息的接口 | 只能成为条件性读取组件 |
| 微信客服 | 目标是微信客户与客服账号的客服会话，非现有混合群 | 收客服会话，不等于群监听 | 客服账号身份，发送有状态、次数、时限条件 | 需改变交互场景，不满足现有群需求 |
| 微信 ClawBot 官方 `Tencent/openclaw-weixin` | 最新发布源码仍只声明 direct 会话 | 未开放本目标所需群会话能力 | 插件通道回复；不能由源码推出代个人微信参加既有群 | 不应当作群机器人方案 |
| QClaw | 官网确认有 macOS 客户端；本次未获取到支持该群场景的官方证据 | 未确认 | 官网定位微信远程办公助手，不足以证明代个人账号全群收发 | 可另评估个人远程操作入口，未确认目标可行 |

上述各项证据、边界和引用见下文。不能把“存档可以读外部会话”与“智能机器人可以发群消息”相加，就称为完整方案：智能机器人的群类型、身份和触发范围并未因此改变。

## 1. 企业微信智能机器人与官方 Node SDK

官方帮助《如何使用智能机器人》“使用场景与触达渠道”规定仅能加进企业内部群，互联群、上下游群及外部群暂不支持；“常见问题”再次重复该边界。官方说明还把群交互定义为识别 @ 机器人的消息后回复。这是对目标混合群最直接的排除证据。[官方帮助](https://open.work.weixin.qq.com/help2/pc/21663)

《接收消息》列举的群触发方式包括 @ 机器人发送文本、图文混排和引用消息；图片、语音、本地文件、视频的单独消息类型限定单聊。因此，“存在 message 回调”不能等价于“接收群里的所有普通消息”。引用通过 `quote` 结构体给出，可用于符合范围的上下文衔接。[接收消息，页面更新 2026-05-18](https://developer.work.weixin.qq.com/document/path/100719)

《智能机器人长连接》通过 `aibot_msg_callback` 收消息，通过 `aibot_respond_msg` 回复，通过 `aibot_send_msg` 主动推送。主动发送的前提是用户曾在该会话向机器人发消息；群 `chatid` 从对应回调中取得。该页规定同一会话回复与主动推送合计限额 30 条/分钟、1000 条/小时，收到回调后可在 24 小时内回复。长连接模式免公网回调地址，但没有扩展到外部混合群；消息结构仍引用相同接收消息协议。[长连接文档，页面更新 2026-05-25](https://developer.work.weixin.qq.com/document/path/101463)

官方 SDK 是上述协议的 Node.js 封装，支持 WebSocket、断线重连、消息事件、流式回复、主动发送、媒体上传等。`BaseMessage` 的 `chatid`、`chattype: single | group` 只表示受支持场景下的会话类型，**不是支持一切类型微信群的证明**。SDK 以 `botId + secret` 认证，发言主体为机器人，不能替换成用户现有个人微信身份。[官方 SDK](https://github.com/WecomTeam/aibot-node-sdk)、[消息类型源码](https://github.com/WecomTeam/aibot-node-sdk/blob/main/src/types/message.ts)

**Mac 影响：**可在 Mac 上开发和运行这类 Node WebSocket 客户端；未发现 Windows 专属依赖。主要阻碍是服务器侧产品权限与群类型，换系统无助于解除该边界。对目标场景无需优先投入 SDK PoC。

## 2. 原群机器人 Webhook / 消息推送

官方文档当前标题是“消息推送配置说明”。开发者向创建后获得的 Webhook 发 HTTP POST，消息进入对应群；文档列举文本、Markdown、图片、文件等发送格式。它不提供接收普通群消息的配套入口，因而不能单独作为 Agent 的双向消息通道。[官方文档，页面更新 2025-08-07](https://developer.work.weixin.qq.com/document/path/91770)

它确实有真实提醒能力：文本的 `mentioned_list` 使用 userid，`mentioned_mobile_list` 使用手机号；text/markdown 内容也可用 `<@userid>`，而 `markdown_v2` 不支持这种 @ 语法。但这些说明**不能证明可 @ 微信外部联系人，亦不能证明可在目标混合群添加机器人**。不要将另一个产品的 @ 参数复制到智能机器人或微信个人号协议。[同一官方消息格式文档](https://developer.work.weixin.qq.com/document/path/91770)

本次已读取的接口页没有明确外部群开放能力；没有为确认这一点实际创建群或机器人。即便暂不判断群准入，仅无群消息读取与个人微信身份两项，就已无法满足需求。Mac 可执行 HTTP 客户端不是关键差异。

## 3. 会话内容存档：有条件的读组件

官方要求企业管理员先设置开启范围、调用 IP 和消息加密公钥。内部员工会得到告知；员工与外部联系人的会话需要外部联系人同意后，企业才可通过 API 获取。可读取范围由企业开启成员和授权决定，个人微信扫码并不能自行取得群所在企业的会话存档权限。[使用前帮助，页面更新 2024-06-11](https://developer.work.weixin.qq.com/document/path/91361)

SDK 提供初始化、分页拉取记录、解密和媒体读取。记录有 `from`、`tolist`、`roomid`、`msgid` 等；文档区分企业内 userid 与外部 external_userid，也包含外部消息。它与“只能处理 @ 触发”的智能机器人不同，适合作为已授权范围的持续归档数据源；但本次没有实测指定混合群内的所有成员、所有消息类型覆盖，不能给出全量保证。文档要求定期拉取，不能取超过 5 天范围的记录；每次最多 1000 条。[获取会话内容，页面更新 2026-01-19](https://developer.work.weixin.qq.com/document/path/91774)

**缺口：**该接口不提供向目标群发送消息、扮演个人微信账号、真实 @ 任意外部成员的发送能力。文本存档示例只有正文，不能据此承诺包含可可靠区分“普通 @字样”与真实 @ 的结构化名单；这项需要正式样本或更明确官方字段来验证。[官方记录格式](https://developer.work.weixin.qq.com/document/path/91774)

**Mac 影响：**官方页面提供 Linux x86、Linux ARM 及 Windows SDK；未列 macOS SDK。若采用这条读路线，可让 Mac 负责开发与控制，将存档服务放到 Linux ARM/x86 容器、虚拟机或服务器。不能把 Linux ARM 二进制当作 macOS ARM 原生库直接加载。[官方 SDK 下载范围](https://developer.work.weixin.qq.com/document/path/91774)

**费用：**本次未核实到官方明确有效的具体资费表，因此不填任何代理商报价或推算价格。是否开通、存档账户范围、企业授权及采购方式需要由有权限的企业管理员确认；即使购买成功，也不会补齐发送缺口。

## 4. 微信客服：改变场景才有意义

官方发送接口按 `open_kfid`（客服账号）与 `touser`（客户）寻址，限定客户处于可由接口处理的客服接待状态。客户主动给客服发消息后，企业可在 48 小时内最多发 5 条；客户继续发送可再次获得发送机会。它适用于一对一客服自动应答，不是获取已有群 `chatid` 后自由聊天的接口。[发送消息，页面更新 2026-02-27](https://developer.work.weixin.qq.com/document/path/94677)

因此这条路能解决“用户进入指定客服入口与 Agent 对话”，但不能保持“个人微信加入原混合群、听所有普通消息、主动 @ 群员”这些条件。运行在 Mac、Linux 或 Windows 不改变其产品边界。[同一发送接口的参数与会话约束](https://developer.work.weixin.qq.com/document/path/94677)

## 5. 微信 ClawBot：以最新官方源码确认范围

腾讯官方仓库 `Tencent/openclaw-weixin` 提供微信通道插件，包含扫码接入、长轮询收取及发送多媒体消息。本次直接读取 npm registry 元数据及静态解包源码，没有执行安装脚本或程序。核验时最新包为 `@tencent-weixin/openclaw-weixin@2.4.9`，registry 发布记录为 2026-09-17 04:20:17 UTC。[腾讯官方仓库](https://github.com/Tencent/openclaw-weixin)、[npm 官方 registry](https://registry.npmjs.org/@tencent-weixin/openclaw-weixin)

2.4.9 的 `src/channel.ts:229–232` 明确声明 `capabilities.chatTypes: ["direct"]`。`src/api/types.ts:203` 虽有可选 `group_id`，但包内没有相应群路由使用，不能把预留协议字段解释为可进入已有微信或企微外部群。当前可验证的实现边界为 direct 会话，未满足该任务的群聊入口和全量监听。[通道源码](https://github.com/Tencent/openclaw-weixin/blob/main/src/channel.ts)、[2.4.9 发布包](https://registry.npmjs.org/@tencent-weixin/openclaw-weixin/-/openclaw-weixin-2.4.9.tgz)

这一路已开源；如以后用户只需从微信直接对话 Agent，可先利用公开实现，无需逆向付费服务。但开源客户端不会增加微信服务器未开放的群能力。官方 README 要求 Node.js >=22.13.0，建议 OpenClaw >=2026.5.12；它也提供引用消息缓存功能，仍属于该 direct 通道的上下文处理。[官方 README](https://github.com/Tencent/openclaw-weixin)

## 6. QClaw：确认 Mac 可用，群需求仍未证实

腾讯 QClaw 官网提供 macOS Apple 芯片、macOS Intel 芯片和 Windows 下载入口，产品定位为微信远程办公 AI 助手。官网“开放平台”描述的能力是 Agent 投稿和应用连接器，并非把个人微信所有既有群会话开放为消息 API。[QClaw 官网](https://qclaw.qq.com/)、[官方开放平台](https://qclaw.qq.com/open-platform)

本次可读到官网页面和公开前端文件，但产品文档页面的实际正文未在读取结果中返回；未核实它提供目标混合群、全量群消息及两类成员真实 @ 的官方能力。故不按“腾讯官方 / 支持微信 / 有 Mac 版”这些宣传或兼容性事实推定目标可行，也不列未核实订阅金额。

## 下一步所需证据

若继续考察商业工具或自建桥接，应要求它在**同一个测试群、同一个登录身份**证明：普通微信成员消息、普通企微成员消息、真实 @ 和文字模拟 @ 的区别、引用回复、主动发送、分别真实 @ 两种身份、断线补收。尤其不能以“普通微信群成功”替代“企微创建的外部混合群成功”。

官方路径中值得保留的方向只有两个，且均需用户改变部分条件：企业愿意协作时，会话存档可研究授权读取；用户接受单聊入口时，可研究已开源的 ClawBot。目标若保持完整，需继续独立核验客户端自动化/桥接路线，不宜为上述不匹配产品先行付费。

## 取证说明

- 企业微信官方开发文档在搜索工具中无法直接展开，后用只读 HTTPS 请求取得官方 HTML，提取并核对正文；以上引用均指向原始官方 URL。
- 腾讯 npm 包只下载到 `/tmp` 并静态读取 `.ts/.md/.json`；没有执行其中代码。版本判断使用固定 2.4.9 发布包，GitHub `main` 链接便于阅读但日后可能变化。
- 部分字段兼容性、授权细则、产品价格和实际群消息覆盖未做账号实测；报告已在对应条目中列明，不把“源码存在字段”写作“端到端功能已跑通”。
