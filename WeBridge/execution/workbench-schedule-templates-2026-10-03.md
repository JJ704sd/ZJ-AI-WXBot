# Windows 定时任务模板与会话配置（2026-10-03）

业务定时索价需要统一模板、按群变量和正文覆盖。原工作台只能逐条填写完整文本，本轮增加本机模板库和按会话保存的内容配置，用于生成可核对的正文，再沿用现有定时任务创建及发送流程。

## 使用流程

在定时任务页打开“模板库”，新建或选择模板，填写名称和正文。占位符写成 `{{客户名称}}`、`{{品类}}` 等形式；变量名支持中文等合法标识符，长度 1～32，不能以数字开头，不支持表达式。一个模板最多 20 个不同变量。

选择会话后填写各变量的值，或明确启用“本会话完整正文覆盖”。模板和会话配置都保存在本机，离线时也可编辑；同名会话按 ID 区分。覆盖启用后使用完整覆盖文本，不继续替换模板变量；空覆盖不会退回通用话术。允许保存未填完的会话草稿，但缺变量、空正文和超长正文不能通过预览。

创建定时任务时，在正文旁选择“从模板填入”，为当前收件会话配置和预览内容，再点击应用。完整预览经过服务端校验，只有用户明确应用才回填任务正文；不会直接创建任务或发送。应用后可继续人工编辑，再核对目标、正文、时间、执行日及窗口，点击原有“创建并启用”。

变量只做一次纯文本替换，不执行代码、读取文件或网络，也不递归解释变量值中的 `{{其他变量}}`。日期需要作为普通文字填写，并会随正文冻结，不会在每次执行时自动更新。模板不会把普通文字 `@姓名` 变成真实提及。

## 内容快照与并发修改

模板是编写工具。任务只保存创建时完整、明确的正文，不保存执行时模板引用。修改或删除模板只影响后续预览，不改变、暂停或取消已建任务；不会在执行时从模板库重新生成内容。此前已明确显示和应用的正文快照仍可使用，任务创建继续按原请求 ID 检查目标和完整规格，变化会触发冲突，不自动生成另一个任务绕过校验。

每个模板有版本号，修改会话配置也更新此版本。保存、删除和预览核对当前版本；过期编辑返回 409，页面保留草稿，由用户明确重新加载。轮询不重写模板编辑内容。切换账号、会话、模板或修改当前预览输入后，旧预览失效，迟到响应不能应用到另一个目标。

已有模板必须匹配当前版本，正文相同也不能绕过其他窗口对会话配置的修改。仅首次创建的同 ID、同内容重试可返回尚未修改的版本 1；更新响应丢失时须重新加载核对，不能凭相邻版本猜测本次更新成功。

## 存储、边界与接口

模板独立存于运行目录 `schedule-templates.sqlite`，所有读写按当前账号隔离。每个账号最多 100 个模板，每个模板最多 500 个会话配置；名称最多 80 字符，单个变量值最多 500 字符。模板正文、覆盖正文和最终渲染结果复用 Hook 发送器的纯文本校验，包括 2000 个 UTF-16 单元、8000 个 UTF-8 字节及控制字符限制，不复制近似字符计数规则。

模板不改变读取白名单或发送权限。保存和预览允许当前可见会话或此前已保存配置的会话，不要求 Hook 在线；真正创建任务仍须通过既有账号、数据源、读取范围与 Hook 绑定检查。预览和保存不会生成发送草稿、执行记录或调用发送接口。

| 接口 | 作用 |
|---|---|
| `GET /api/schedule-templates?account=…` | 当前账号模板摘要 |
| `GET /api/schedule-templates/item?account=…&id=…&groupId=…` | 模板正文、变量名、版本和指定会话配置 |
| `POST /api/schedule-templates/save` | 按版本新增或修改模板名称、正文 |
| `POST /api/schedule-templates/profile` | 保存指定会话变量与可选完整覆盖正文 |
| `POST /api/schedule-templates/preview` | 按版本校验并生成完整正文，不保存 |
| `POST /api/schedule-templates/delete` | 按版本删除模板及其会话配置 |

模板 ID 由页面生成，新增版本为 0。会话配置和预览使用 `{account,id,version,groupId,values,overrideText}`；`overrideText:null` 表示模板模式，字符串表示完整覆盖模式，包括尚未填写的空草稿。服务端在请求边界校验，在内部复用已验证的契约。接口沿用 Host、Origin 和 CSRF 校验，返回字段不暴露数据源路径。

四个模板 POST 接口允许最多 256 KiB JSON，以容纳 20 个变量分别填写 500 字符的合法草稿；其他接口仍为 32 KiB。保存草稿的大小不代表最终正文可发送，预览仍校验展开后的完整文本上限。

能力声明为 `runtime.capabilities.scheduleTemplates`。无此能力或非数据库模式时隐藏入口；既有任务、创建请求和账本无需迁移，旧的任务运行逻辑不依赖新增模板表。原来的定时创建接口没有增加模板 ID 或预览 token。

## 验证范围

完整 Python 回归 441 项通过，无跳过，耗时 112.158 秒。新增 12 项模板服务测试、5 项 HTTP 集成测试，覆盖账号隔离、离线操作、同名会话、重启持久化、版本冲突、请求大小、缺失变量、空覆盖不回退和 Unicode 文本边界。共享文本校验提取后，原 Hook、定时及自动回复测试均包含在完整回归中。日志为 `.runtime/workbench-schedule-templates-20261003-tests.log`。

HTTP 联调使用临时 SQLite、合成账号和录制传输。创建任务使用模板预览的完整正文；随后修改、删除模板并重复提交原任务，仍只有一条任务，执行两次 tick 只记录一次原正文提交；人工修改正文再用同一请求 ID 创建被拒绝。没有向真实微信发送消息。

10 组 Node 界面检查通过，其中模板检查 17 项，覆盖迟到预览、账号和目标切换、冲突草稿保留、正文显式应用及手动修改保护。独立审查发现的相邻版本误判与 `__proto__` 变量丢失均用失败反例复现后修复；前者严格匹配版本，后者通过 `Object.fromEntries()` 保留合法键，无需额外限制变量名。

窄屏截图审查还发现预览被固定底栏覆盖，单纯检查 DOM 文本不能证明用户看得到。新增浏览器几何与遮挡检查后实际失败：正文底部 808 像素，底栏从 744 像素开始。已取消模板弹窗的固定底栏，使正文与操作按钮正常滚动；失败记录保留在 `.runtime/schedule-template-layout-red-20261003.log`。

修复后 Chrome 模板流程 33 项全部通过；现有执行窗口 30 项、每周计划 28 项和批量暂停 36 项也通过，共 127 项。浏览器所有业务 API 均为模拟，覆盖 CRUD、同名会话、配置回读、冲突、迟到响应、显式应用、任务纯正文请求和窄屏正文／按钮可达。已查看 `output/playwright/schedule-template-{desktop,mobile,apply-mobile}.png`，预览与应用按钮无遮挡。日志为 `.runtime/schedule-template-browser-20261003.log` 及 `.runtime/template-regression-{schedule_window,weekly_schedule,schedule_pause}-20261003.log`。
