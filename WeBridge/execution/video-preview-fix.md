# 视频只显示 JPG：诊断与修复

日期：2026-09-21。客户端为既有 Linux 微信 4.1.1.8 ARM64，页面 `http://127.0.0.1:8787/`。

## 原始故障

“中技AI cosplay”新收到的普通视频，localId=56，serverId=`5450782503465515206`。消息声明时长 7 秒、大小 1,000,767 字节；加载接口却返回 19,778 字节 `image/jpeg`，`previewOnly=true`。

最小复现：

```sh
python3 web_mvp/diagnostics/check_video.py
```

修复前连续两次输出 `FAIL: this video resolves to a cover or unavailable attachment, not playable video bytes`，定位到服务端返回封面，不是浏览器把 MP4 错认成 JPG。

## 原因

1. 客户端缓存只有 `_thumb.jpg`，没有完整 MP4。原接口只有缓存读取，没有下载步骤。
2. 候选遍历先遇到资源索引中的封面就返回，可能漏掉后面的硬链接完整视频。独立文件夹回归测试确认了这个潜在问题。
3. 前端虽提示仅封面，仍把封面放入通用“打开预览 / 下载”流程，造成已经加载视频的错觉。

## 修复依据与实现

- 本地客户端二进制视频资源构造流程在 `0x4bea6e8` 附近拼接 `authkey:` 请求头。无授权头的官方下载测试返回 403；用户明确授权只向对应微信官方文件服务器使用视频自带凭证后，带授权头的请求返回 206。
- 这条视频的官方下载返回加密数据，默认每段最多 512 KiB。实测两段为 `0-524287/1000768` 与 `524288-1000767/1000768`。
- `video_download.py` 验证官方 HTTPS 域名和端口、拒绝重定向、限制大小/时间、验证连续 Content-Range，取得全部分段后 AES-128-ECB/PKCS7 解码，再验证明文长度、MP4 文件头、消息原 MD5。凭证不输出到网页或日志。
- `media_container.py` 优先完整视频，再按需官方下载，最后才降级为封面。下载结果在独立私有缓存中原子写入，不修改微信数据库或客户端媒体目录。
- `rich_ui.js` 将“仅封面”单独展示，并提供“下载并播放视频”；不把封面作为视频提供“打开预览 / 下载”。显示消息中声明的时长和大小。

## 验证结果

- 原始复现命令已通过：`video/mp4`，1,000,767 字节，`previewOnly=false`；读取前 32 字节返回 206 且含 MP4 `ftyp` 标记。
- 明文 MD5 与消息提供值一致：`7428d7cb8df997adb4a82e647eb0ee4d`。
- ffprobe：H.264 / avc1，540×960，实际时长 6.6 秒。
- 实际网页点击“加载视频”及“打开预览”，显示 `video_56.mp4`。点击播放后，画面变化并从 0:00 播放至 0:06 结束。HTTP Range 验收通过；浏览器进度跳转未单独标记通过。
- 33 项回归测试全部通过，新增 5 项验证封面时官方下载、完整缓存优先、授权错误、官方域名限制、损坏/不完整分段不作为可播放视频提供。
- 没有向群里发送新消息，没有通过 Linux 窗口点击视频或注入下载探针。

当前支持的是本次真实样本使用的企业微信视频官方下载格式，不能由一个样本推断所有个人微信 CDN、合并记录内视频或大视频均已适配。账号登录状态和读取范围校验继续生效。

播放验收完成后，客户端报告 `logged_out` 并显示退出提示；已向用户询问是否在主动测试退出，原因待确认。网页后台继续运行，离线时附件访问按账号隔离规则停止，已验证的视频缓存保留。后续重测需先在页面扫码登录。

预防同类问题的关键是覆盖“收到媒体元数据，但完整文件尚未下载”的真实流程；封面、完整文件和下载失败必须分别处理，不能以 HTTP 成功或找到任意缓存作为媒体可播放的验收标准。
