# Windows 本机媒体接入验收（2026-09-28）

本轮在 Windows、Python 3.14.6 上接入当前账号的数据库副本与本机附件缓存。用户分别授权图片密钥、hardlink.db / message_resource.db 数据库密钥的只读提取；密钥、解密副本、缓存与带私有标识的验收报告均留在 Git 忽略目录。没有发送消息、请求 CDN 或上传附件。

## 实现

- 数据源新增可选附件索引及图片密钥路径；旧配置默认仍只复制业务库。附件索引与业务库共用稳定复制、逐页解密、WAL 合并与 SQLite quick_check，不对原库运行 SQLite。
- 新的 Windows 加载器按消息索引及摘要定位图片、视频、文件；V2 DAT 使用已验证的本机图片密钥。完整文件有 MD5 时必须匹配，缩略图和视频封面明确区分。
- 合并记录内附件支持五层索引，Rec 文件限定在当前会话和月份下有界查找，必须匹配 fullmd5；不根据同名或相同大小猜配。
- 复用现有图片、MP4、PDF、文本与下载界面，以及 HTTP Range。客户端收到随机附件 ID，不收到磁盘路径、原始消息 XML、CDN 凭证或密钥。
- 每次读取附件仍检查账号、会话读取范围和消息状态；撤回/取消读取后拒绝访问。相同消息跨副本刷新可以继续读取缓存，消息内容变化则失效。

## 实机证据

6 个业务及媒体索引数据库均通过密钥匹配；图片密钥经两份独立 V2 图片解码验证。

| 项目 | 实测结果 | 范围 |
| --- | --- | --- |
| 图片 | 6 份完整图片、111 份缩略图可解析 | 各会话最多 2,000 条的本地历史诊断，可能包含同一图片的多次消息引用 |
| 视频 | 1 份完整 MP4、9 份仅封面 | 完整 MP4 来自合并聊天记录，8,353,068 字节，摘要匹配 |
| 图像解码 | 126 次 Pillow 校验通过 | 包含 117 个图片消息附件及 9 个视频封面；不等于 126 张独立原图 |
| 当前工作台图片 API | PNG，207,462 字节，非缩略图 | 主服务 8787，HTTP Range 返回 206 / 64 字节 |
| 浏览器图片 | 800×410 图片实际解码显示 | 主工作台页面 |
| 浏览器视频 | 448×960，133 秒，readyState=4，无媒体错误，播放进度已推进 | 临时本机 8788 服务使用同一生产附件处理器、独立读取状态；并非完整播放到结束的验收 |
| 视频 Range | 206，1,024 字节 | 上述完整 MP4 |

网页仍显示每会话最近 200 条，因此历史诊断的成功数量不等于当前页面可见数量。当前最近消息样本中读取到 25 个图片附件（6 完整、19 缩略图）与 2 个视频封面。

## 边界

- 本机未缓存、图片尾部无法确认、WXGF/部分表情格式、完整摘要不符均返回待处理原因，不返回其他会话或同名文件顶替。
- 历史诊断另有 60 个图片附件、245 个表情及 4 个视频未就绪；并未打通所有图片/表情格式或通用 CDN 下载。
- 普通文件/PDF/文本路径已做合成验证，当前真实样本没有完成普通文件验收。
- 语音转写、图片 OCR、视频内容理解不在这次媒体解码与预览实现中。

## 复验

完整合成回归 **220 项通过**；两个前端脚本通过 `node --check`。测试退出码为 0，同时已有 HTTPError 拒绝场景的测试夹具产生一条临时文件清理 ResourceWarning；该警告不是实机附件解码结果。

在项目目录运行，按当前 Python 环境准备原有测试依赖。Windows 测试的 TEMP / TMP 应指向真实长路径，避免系统短路径别名影响既有字符串路径断言。

```powershell
python -X utf8 -W error::ResourceWarning -m unittest discover -s web_mvp -p 'test_*.py' -q
node --check web_mvp/static/app.js
node --check web_mvp/static/rich_ui.js
```

本地实机诊断使用 `web_mvp/diagnostics/check_windows_media.py --config <database-config.json> --report <私有报告路径> --limit 2000`；可用 `--snapshot` 指定保留的独立副本，避免自动刷新清理正在检查的旧副本。报告含消息定位信息，应始终放在 `.runtime` 等私有目录，不提交。
