# Windows 工作台人工待办（2026-10-03）

本轮补齐业务需求中的本机人工处理队列：保留原群、发起人、原消息、原因、负责人、时间和处理状态，支持无负责人任务统一领取。它尚未通知负责人，不应对外称为“已转交”。实现和验证使用合成 SQLite 副本、录制发送替身与模拟浏览器接口，没有启用真实群规则或发送微信消息。

后续已增加按群默认负责人配置和负责人／未分派筛选，见 [负责人分派说明](workbench-handoff-routing-2026-10-03.md)。分派只为新待办填写本机标签，状态仍为待领取；下方领取、完成、释放及撤回语义保持不变。

后续新增可单独批准的 [负责人私聊通知](workbench-handoff-notifications-2026-10-03.md)。本页保留最初本机待办轮次的实现及验证记录；当前版本启用通知后，新任务可进入独立发送队列，详情另列通知结果，领取和撤回等任务变更会取消尚未开始提交的通知。未启用时仍仅保存本机待办，不能依据本机状态宣称负责人已收到。

## 使用与状态范围

连接自动更新的数据库副本，确认本人身份，勾选读取目标群。在群规则中选择“转人工待办”，启用并保存。此模式不要求连接 Hook；后续满足新消息条件的真实结构化 @ 本人进入左侧“人工待办”。普通文本中的 `@昵称`、@所有人、自身消息、身份未知及撤回消息均不进入队列。

固定文本回复与转人工是同一个群规则的两个互斥模式。待办模式不会调用发送接口，也不使用固定回复间隔抑制第二个请求；一条合格消息对应一条待办，跨分片重复仍只入库一次。启用时建立完整基线，启用前已有消息不补入队列；入站有效窗口仍为 120 秒，启用同一秒的消息不触发。

队列只展示当前数据源账号、当前存在且勾选读取的群。可按状态与群筛选、翻页，第一页每 10 秒更新。历史页不随轮询跳动，手动刷新回到第一页。切换账号或读取范围时清除原列表、详情和输入，迟到的旧请求不能恢复显示。

| 操作 | 状态变化 | 负责人 |
|---|---|---|
| 领取 | 待领取 → 处理中 | 必填，最多 80 字符 |
| 释放 | 处理中 → 待领取 | 清空，回到统一队列 |
| 完成 | 处理中 → 已完成 | 保留 |
| 重新打开 | 已完成 → 待领取 | 清空 |

处理备注最多 2000 字符，随本次变更保存。每次变更带版本检查；页面过期时返回 HTTP 409，刷新详情并保留尚未保存的输入，需重新核对后操作。处理记录按版本展示最近 100 次，超出时明确提示；数据库保留完整记录。

上述状态只针对单条待办。领取、完成、重新打开均不发送微信消息，也不切换群规则。恢复固定回复必须在原群显式选择“固定文本回复”并保存，重新检查 Hook 并建立新基线。定时发送独立配置，不受待办状态影响。

手动断开发送只暂停固定回复，人工待办继续接收。数据源故障、取消群读取及工作台重启会暂停待办规则，需要重新核对启用；已创建的任务保留。浏览器关闭不影响已启用规则的后台入队，工作台服务和副本更新仍须运行。

## 撤回与持久化

队列列表是已保存摘要。启用规则的入站扫描在处理候选消息前核对当前副本支持的全部撤回记录；打开详情及点击完成还会独立核对，即使群规则已关闭。历史任务超过 120 秒仍会检查撤回。

发现撤回后清空待办保存的原文，取消正文截断标记，增加一次版本与处理记录；负责人及处理状态不自动改变。重复读取同一撤回不会重复增加版本。完成时若新发现撤回，旧版本操作返回冲突，先显示最新状态再由用户决定。副本正在更新或存在阻断性解析问题时，不把无法核对的详情当作最新事实。

原文最多保存前 2000 字符并标记截断。入站事件领取与任务、创建记录在同一 SQLite 事务内；入队失败不会留下已领取但没有任务的事件。执行历史只保存“已创建本机待办，未通知负责人”和任务标识，不重复保存可撤回的触发正文。

新增 `handoffs` 与 `handoff_changes` 表位于忽略目录下现有 `windows-auto-reply.sqlite`。旧规则启动时补齐 `mode=reply` 并继续按既有规则关闭；旧客户端未提供 mode 时保留当前模式，不会静默恢复发送。没有另建待办同步数据库或自动发送重试队列。

## 接口与复验

`GET /api/handoffs` 支持 `account`、`status`、`groupId`、`limit`、`cursor`，先筛选再分页，默认 50 条、最大 200 条；游标绑定账号、读取范围和筛选条件。`GET /api/handoffs/detail` 返回单条任务及处理记录。`POST /api/handoffs/action` 使用既有同源与 CSRF 保护，接收 `account,id,version,action,owner,note`。这些接口不启动 Hook，不发送负责人通知。
