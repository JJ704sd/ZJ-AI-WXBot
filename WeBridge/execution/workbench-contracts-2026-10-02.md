# 工作台业务审计与契约精简（2026-10-02）

依据 `specs/mixed-group-business-requirements-2026-09-21.md` 中入站识别、任务账本、发送证据分层及运维日志要求，继续改进本地 Windows 工作台。本轮只使用合成数据库和录制发送替身，没有真实微信读写、Hook 连接或服务配置变更。

## 已实现

自动回复领取事件时，在同一次持久化中冻结当次 `replyText`、`decision` 和触发消息的标识、发起人、时间及前 2000 字符。即使因冷却跳过、发送结果未知、规则后来被修改，原审计内容仍保留。执行记录以白名单返回触发内容，支持查询触发正文和联系人名称，并展开查看。Hook 草稿不存在时可使用事件自身已保存的当次话术；旧事件未保存的数据保持缺失，不用当前规则补造。

定时任务按实际阶段记录失败：消息副本读取错误或阻断性解析警告发生在 `send_automatic` 调用前，标记 `not_submitted`；调用后的异常无法证明微信是否受理，保持 `unknown`。两类情况均暂停任务且不重发原任务。非预期异常先保存可确认的阶段结果，再向上抛出，不再直接吞掉。后续已将纯显示名解码失败从身份和内容错误中分离，保留警告并按原会话 ID 执行，见 [持续运行改进](workbench-operations-2026-10-02.md)。

自动回复的异常捕获缩至声明的读取、绑定和 I/O 错误。发送阶段通过 `finally` 保留已持久化领取和未知结果，意外程序错误会继续向外传播。没有放宽账号、群、本人身份、真实 @、冷却、进程绑定或防重条件。

## 删除的重复逻辑

- 消息历史 HTTP 层透传 `limit`，由查询入口统一校验；统一拒绝 `01`、`0001`、`+1` 等非规范整数。
- 执行历史游标删除从未参与 SQL 查询的 `ceiling` 字段；降序分页仍使用签名的 `last` 坐标和完整查询范围绑定。
- 历史页面直接读取同版本接口必需的消息、记录、警告和游标字段，不再把缺字段悄悄解释成空列表或末页。
- 消息摘要直接使用解码器已保证的字段，去除 SQL 已转换坐标的重复转换；关键词每页归一化一次，日期上下界随查询上下文复用。
- 删除“2 MiB 单页超过 16 MiB 总缓存上限”的不可达降级分支，保留真正的累计缓存淘汰。用实际超过 16 MiB 的中文消息分页测试替换不可能的 1 字节缓存配置测试。

外部输入、数据库坏数据、游标范围、读取权限、资源限制和发送身份校验继续保留。没有以减少行数为目标删除有业务依据的保护。
