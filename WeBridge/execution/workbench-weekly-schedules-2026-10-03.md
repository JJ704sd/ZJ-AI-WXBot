# Windows 每周执行日配置（2026-10-03）

业务需求要求每群在每个配置执行日执行一次。原 Windows 定时任务只能选一次或每天，无法表达周一至周五、每周一三五等安排。本轮新增“按星期重复”，仍使用现有任务、执行账本、Hook 绑定和提交入口，没有另建调度服务。

## 操作与时间语义

在“定时任务 → 新建任务”中选择“按星期重复”，勾选周一至周日的任意非空组合，填写北京时间和完整发送文本。新建窗口预选周一至周五，所选星期始终明确显示，至少保留一天才能提交。任务卡显示执行星期、计划时间及下一次时间；修改发送内容、收件会话或执行日仍须取消旧任务后新建。

创建和恢复都取严格晚于当前时刻的下一次选中日期。例如只选周一 09:00，在周一 09:00 创建或恢复会安排到下周一，不借用旧计划的迟到窗口。每周任务有历史执行记录后仍可暂停、恢复；未知结果的旧一期不会因此重发。

任务持续启用但漏过多次轮询时，只为真正配置的执行日补记 `missed`，不把未选择的日期统计成漏执行。若最近到期的一次尚在 120 秒窗口内，只提交该次；更早的次数只入账，不补发。过去账本与本次领取在同一事务内完成，保留原任务 ID 与按计划时刻生成的运行 ID。

星期依据计划时刻的北京时间日期，允许窗口保持为计划后 120 秒，包含边界。因此周五 23:59 的计划在周六 00:00 仍可提交周五那一次；周六不会产生新一期。超过 120 秒则登记错过。北京时间固定 UTC+8，不依赖 Windows 当前时区。

手动暂停、工作台重启、数据源或 Hook 变化后的恢复只安排未来日期，不为暂停期间补造执行记录。未到期、未选中日期也继续检查账号、读取范围和 Hook 绑定，不能借此绕过暂停保护。每周模式仍只发送普通文本，不代表支持真实 @ 或节假日调休。

## 请求及已有数据兼容性

沿用 `POST /api/jobs`，新模式为 `mode="weekly"`，增加 `weekdays` 数组：整数 `1` 至 `7` 分别表示周一至周日。数组须非空且无重复；布尔值、字符串和越界值返回 400。服务端在入口排序后建立冻结的任务规格，同一请求 ID 的星期顺序变化命中原任务，改变星期集合则拒绝。

`once` 和 `daily` 保留原有请求及持久化规格，不增加存储默认字段。其他模式携带 `weekdays` 会明确拒绝，避免忽略调用方的执行日限制。返回的任务视图统一提供 `weekdays`：每周为实际选择、每日为 `[1,2,3,4,5,6,7]`、一次性为 `[]`；内部仅在每周模式读取已校验的持久化字段。

| 组合 | 支持范围 |
|---|---|
| 新服务读取既有一次／每日任务 | 维持原 ID、规格、账本和下次时间；启动仍按原规则暂停 |
| 原一次／每日请求向新服务重试 | 同请求 ID、同规格命中原任务，不自动恢复 |
| 新页面与新服务 | 支持三种模式，包括每周任务持久化、暂停和恢复 |
| 新每周请求发往旧服务 | 旧服务拒绝未知模式；不能视为创建成功 |
| 旧页面或旧服务管理每周任务 | 不作为兼容状态；更新后需刷新页面，含每周任务的运行目录不要交给旧服务恢复执行 |

本轮没有修改实际运行配置或运行数据库，也没有重启工作台。创建每周任务前需使用更新后的服务与页面。

## 复验

从 `WeBridge` 目录运行，全部使用合成时钟、合成数据库及录制发送替身：

```powershell
D:\Anaconda\python.exe -W error::ResourceWarning -m unittest discover -s web_mvp -p 'test_weekly_scheduler*.py' -v
D:\Anaconda\python.exe -W error::ResourceWarning -m unittest discover -s web_mvp -p 'test_windows_scheduler.py' -v
node web_mvp/diagnostics/check_schedule_controls.cjs
node web_mvp/diagnostics/check_weekly_schedule_controls.cjs
```
