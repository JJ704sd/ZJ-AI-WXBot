# Windows 定时任务按会话和全部暂停（2026-10-03）

业务需求的定时索价包含“单群／全部暂停”。此前 Windows 工作台只能逐条暂停任务，本轮增加当前账号全部任务和指定会话全部任务的暂停入口，沿用现有 SQLite 任务及执行账本，不新增调度服务或持久化总开关。

## 操作和生效范围

定时任务页新增会话筛选，选项来自当前账号保存的任务，因此已经取消读取或当前无法获取元数据的会话仍可选择。选择“全部会话”后点击“暂停全部定时任务”，选择具体会话后点击“暂停本会话任务”。按钮旁显示该范围的已启用任务数；搜索词和任务状态只筛选列表，不缩小暂停范围。

本机服务可访问、当前账号明确时，即使数据库副本忙碌或异常、Hook 离线，仍可请求暂停。操作只影响定时任务，自动回复和人工待办保持独立。重复暂停返回实际变更数量，可能为零；已暂停、结束和取消的任务保留原状态、原因及历史。

服务收到有效请求后先登记暂停，再等待正在占用的执行锁。调度器在开始下一条任务前检查登记状态，发现请求就退出本轮。当前已开始处理的一条允许结束，尚未提交的这条也可能继续提交，已经提交的内容不会撤回。副本更新等其他操作也共用这些锁，因此不承诺固定响应时间。按会话暂停会使本轮提前结束，其他会话任务仍保持启用，可在后续轮询中执行。

暂停成功后显示服务端实际暂停数量。若连接中断或服务报错，页面显示“未确认暂停结果，请刷新核对”，不会自动重试。等待期间禁用重复暂停、新建和单条操作；切换账号后，旧请求的成功、失败或结束不会覆盖新账号状态，也不会解除新请求的等待状态。暂停成功后才返回的旧状态轮询不会把任务重新显示成已启用，下一次正常轮询仍采用服务端状态。

恢复继续沿用逐条检查账号、来源和 Hook 绑定的入口，不提供一键全部恢复。本次操作只暂停事务提交时范围内已启用的任务；随后明确新建或恢复的任务可正常启用。没有永久禁止该账号发送的开关。

## API 与事务

Windows 数据库模式使用 `POST /api/jobs/pause-all`，请求为 `{account, groupId?}`。省略 `groupId` 或传入空字符串表示当前账号全部任务；非空字符串表示精确会话 ID。`null`、布尔值、数组及超过 256 字符的范围返回 400，不能误解成全部。不存在的会话返回零条变更。接口沿用本机 Host、Origin 和 CSRF 校验。

返回 `{pausedCount, jobs}`，其中 `jobs` 是提交后当前账号的完整任务列表。后台在等待锁前核验账号，取得锁后再次核验，账号变化则拒绝。所有匹配的启用任务在一个事务中改为暂停，任务 ID、原顺序、内容、执行日、下次时间、来源绑定和历史执行记录均不变。事务失败整批回滚；并发请求使用计数登记，任一请求结束或失败不会提前解除其他请求的阻止状态。

实现只在 HTTP 参数和账号边界校验，更新时信任现有任务数据契约。没有为内部任务重复解析和逐项重写，也没有失败后假装成功或自动重试。
