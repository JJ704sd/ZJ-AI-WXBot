# 私聊分析助手 1.2.0：界面更新与验证

本轮根据用户对 UI 的反馈，调整个微/企微私聊主页、聊天足迹、原文检索、画像复核和离线 HTML 统计报告。设计先写入 `docs/local-chat/私聊界面美化-v1.2-20261022.md`，再分别委派主页、统计和画像三个实现任务，由主 Agent 统一主题、整合验证并构建。

## 视觉与交互变化

- 新增私聊独立主题：浅灰绿背景、绿色主操作、白色圆角面板、较大的标题与数字、统一控件间距。共享群聊主题常量未修改。
- 主页将联系人选择与阅读分区，私聊分析入口保留在阅读区顶部；文件格式、图片网页、目录等次要操作集中到“更多设置”。日期展开和批次提示出现时动态分配阅读空间。
- 聊天足迹用四项指标、消息趋势和小时分布构成概览。长历史按月或年汇总绘图，明细保留原值；未知方向、时间及解析缺口保持可见。
- “聊天时光”使用暖色月历与原文回忆卡。检索表隐藏技术列，选中后仍能查看消息 ID、ref 和完整原文。
- 画像复核用左右分栏对照观察和原消息；限制说明可展开。三项核对默认未选，备注与确认区并排布局，保存仍在后台执行，失败可重试。
- HTML 报告使用同一色系、较大数字、柔和渐变和响应式卡片；来源标识可展开。报告仍默认不包含聊天正文，没有外部资源或脚本。

## 验证范围

最终相关回归包含存储、直接会话、统计、分发、身份绑定、原生界面、双端集成和小窗口检查。执行明细及包验证以同目录 JSON 和构建日志为准。

已完成的定向检查共 66 项：核心 48 项、原生 UI 与双端整合 17 项、原有群聊解析复用与显式重解析 1 项；运行身份扫描 119 个运行文件，0 个问题。主 Agent 在整合中修复了检索结果区被挤空、日期展开导致按钮越界、复选框文本被备注区挤压，以及画布超过父面板造成刻度裁切的问题，并加入了对应几何断言。相关修订均在最终构建前复验。

原生检查使用合成数据，覆盖主窗口 1000×700、统计和画像 900×620，以及较大窗口。验证了控件边界、原文空间、三项核对全文、图表刻度位于父容器内、异步检索/保存、分页、清空恢复和取消状态。没有读取真实账号、聊天、媒体或密钥。

本轮原生桌面截图接口不可用。`private12-layout-preview/index.html` 是由实际 Tk 控件坐标、文本和图形生成的 SVG 布局预览，**不是原生窗口截图**；原生控件边框、文本换行、圆角与焦点效果可能有差异。HTML 报告示例为实际渲染输出，全部使用合成数据。预览辅助文件不会进入两套 Skill ZIP。

## Windows 包验证

1.2.0 桌面和画像 EXE 使用现有项目依赖重新构建，打包器实际检查版本、角色和 direct 能力。验证脚本使用隔离数据目录及不含 Python 的子进程 PATH，检查两套包的合成私聊解析、prepare/stage/show、中文候选、PowerShell wrapper、统计报告、关键词分页、禁止写进源导出、跨客户端拒绝以及空配置原生窗口启动。

以上实际包验证已通过，完整结果见 `private-analysis-1.2.0-compiled-validation.json`。每端 ZIP 27 个文件，CRC、文件集合及逐文件哈希均通过。旧版持久化请求与来源 ID 兼容性仍与 1.0.0 实际 EXE 比较，两个客户端均一致。人工复核及画像入库契约未变，没有新增模型 API、生产依赖或定时任务。

## 已知边界

- 此处是定向回归，不代表全仓测试通过。原有群聊 `WeComSetupFlowTests.test_saved_inactive_account_is_explicit_and_running_choice_only_edits_form` 在本轮单独复测仍于子进程 10 秒等待条件处超时；与既有验证记录中的用例相同。本轮没有修复该问题，也没有将其归因于本次私聊主题改动。
- 未验证真实账号、多种 Windows DPI/主题组合、WorkBuddy 导入或宿主实际模型分析。合成测试不证明真实画像结论正确。
- 旧版 v41、1.0.0、1.1.0 交付保留，最终文件哈希复核见 `private12-delivery-validation.json`。本轮未提交、推送或发布 Git。
