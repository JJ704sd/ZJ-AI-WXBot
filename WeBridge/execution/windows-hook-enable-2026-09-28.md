# Windows Hook 本机发送启用（2026-09-28）

## 本次结果

当前 Windows 客户端版本为 4.1.15.13，Weixin.dll 的 SHA256 与仓库固定适配值一致。本次安装项目内 Frida 17.19.0，启动本机发送桥；状态为 `ready` / `available=true`。

旧启动代码固定读取 D 盘安装位置，而本机微信在 C 盘。现改为通过 Toolhelp 模块枚举，从业务数据库唯一所属 PID 获取实际加载的 Weixin.dll 路径；仍校验固定 SHA256、进程创建时间、当前账号以及发送入口字节，未知版本不放行。每次提交前再次核对实际模块路径与摘要。

用户明确授权后，仅向文件传输助手发送一次“Windows Hook 本机发送测试”。返回状态从 `submitted_unconfirmed` 变为 `local_record_observed`：副本出现一条新增的本人同文记录。未取得服务器回执，不将本机观察写成对端送达或已读。截图中的群聊草稿没有提交；未创建定时任务或自动回复。

Hook 相关合成测试 **53 项通过**。本次没有重新执行上一轮完整 220 项回归；上一轮媒体实现和其他工作区改动均保留。私有草稿及结果位于 `.runtime/web_mvp-database/`，不提交原始标识或本机凭据。

## 使用

刷新工作台，确认右侧显示“发送已连接”。选择已勾选读取的会话，输入正文，点击“核对并发送”，核对目标和内容，再确认。当前支持纯文本、中文、换行和 emoji；附件发送、真实 @、定时和自动回复尚未接入 Windows 路线。

需要停止时点击“断开发送”。当前 Frida 的保护性常驻资源会保留到微信客户端正常退出；停止网页后台会停止发送桥，不会退出微信。重新启动工作台后，通过“连接发送”重新启用，不自动附加或发送。

## 后续定时发送需求与验收

Windows 数据库模式目前不会启动原 Linux 调度线程；不能仅显示原有定时 UI 就认为功能已接入。

下一阶段优先实现每日定时纯文本：

1. 创建前确认账号、当前已读取的会话、正文、北京时间及生效日期；默认不带真实 @。任务启用是对所列范围的定时发送授权。
2. 使用独立的 Windows 调度持久记录，复用 Hook 的版本/账号校验与持久幂等能力；运行前再次验证会话仍在读取范围。不要通过伪造人工确认或复用已过期草稿绕过确认流程。
3. 提供任务列表、下次执行时间、停用/取消、执行状态与本机回读结果；断开桥或更换账号时暂停，重新连接后不补发历史任务。
4. 延迟窗口建议沿用 2 分钟；超时跳过。已提交但结果不明时不自动重发。重启恢复只能恢复未来计划，不重放发送中的请求。
5. 验收覆盖同日去重、重启、账号切换、取消读取、桥断开、取消与触发竞态、电脑休眠、超时及夏令时无关的北京时间计算；先合成测试，再针对用户明确授权的会话和内容做一次真实定时验收。

一次性指定日期发送、工作日/每周规则、附件定时发送及自动回复可另行排期，不在当前已启用能力中。
