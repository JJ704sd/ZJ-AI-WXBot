# 群聊 v44 / Skill 1.30.0 验证记录

2026-10-23。基于 v43 更新个微、企微群聊脚本；私聊交付仍为 1.7.0。先完成规格，再由 UI、Runtime、Performance 三个子 Agent 分工开发，主 Agent 整合、验证与打包。

## 实际改动

- 企微引用索引只保存 token 对应的表和 rowid，命中后读取正文。保留所有候选、跨表匹配、歧义判断、同群限制和原始出处，不修改源数据库。
- 批量发布及修复在操作开始、结束校验源副本，合并同一次操作内的嵌套重复检查。作用域隔离线程，退出或异常后不保留跨操作信任缓存。企微数据库及个微语音库保留完整摘要验证，个微其他库沿用已有文件身份、头部和元数据检查。逐群解析前后的校验不变。
- 最后一群保存后源副本发生变化时，批次标为 partial，保留已验证的正文与检查点；界面提示重新加载，宿主回执为 needs_source / ok=false，不再误报 completed。
- 后台群先保存可复核材料，打开时再建立阅读索引；解析下一群时仍可打开此前结果。显示当前群处理条数、分析整理和保存阶段，不为百分比额外全表计数。
- 首群尚未完成或只完成部分群时，重启保留当前源中有效群的选择，复核状态独立验证。首次快照摘要在后台加载时准备，勾选不再扫描大文件；失败加载保留旧状态。

v43 的明文/密文混合库、选定语音库取钥、企微分库密钥、无效字段保留和秒/毫秒时间兼容继续保留。没有放松密钥验证、页认证、WAL 或 SQLite 快照检查，没有新增生产依赖。

引用缓存内存下降 85.52%，测的是 Python 保留对象大小，不是整个进程 RSS。命中引用多了一次按位置读取，后续 100 次引用约多 0.027 秒；完整引用 JSON 摘要一致，源库未修改。

8 群场景每群 400 条，加 64 MiB 合成数据库填充，个微另有 64 MiB 语音库；前后各两次，普通 Windows 文件缓存。发布/修复源摘要由 9 轮降为 2 轮，读取量下降 77.78%；每轮均成功发布、恢复 8 群，全部 JSONL 与复核版逐字节相同。后台预热把首次解析前的快照清单计算移到加载阶段，属于耗时转移，不声称消除了该检查。

10 万条场景两端逐行核对消息 ID、正文、顺序及状态摘要，均与 v43 一致，正式文件保存与重启恢复成功。v44 使用后台群延迟阅读路径；以后打开群仍需支付阅读索引成本。基准为本机合成普通文本和明文源，不包括真实取钥、媒体、网络或硬盘冷启动，少量样本耗时不代表普遍吞吐率。
