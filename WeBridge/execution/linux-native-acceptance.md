# Linux 原生接口：指定混合群双向验收

日期：2026-09-21。**已证明可在本机 ARM Mac 上，通过隔离 Linux 客户端内部接口完成无点击发送和真实 @，并用数据库临时副本接收普通消息、识别测试账号被 @。** 这是可行性 PoC；不宣称生产可用、纯协议或跨版本兼容。

## 已通过的四项

| 能力 | 实测证据 | 范围 |
| --- | --- | --- |
| 无界面主动发送 | `NATIVE-005`：`uiOperations=0`；服务器 `baseRet=0`、消息 `ret=0`、收件群和 clientMsgId 均匹配；非零 newMsgId | 中技AI cosplay |
| 真实 @ 企业微信成员 | 请求含真实 `atuserlist`；用户确认消息可见且陈佳豪收到真实 @ 提醒 | 火运科技的陈佳豪 |
| 接收普通消息 | `RECV-001` 来自另一 `@openim` 成员，非测试账号自己，消息类型为文本 | 同一指定群 |
| 识别自己被 @ | `RECV-002` 的 source XML 中，`atuserlist` 精确包含测试账号 wxid；普通消息没有该标记 | 同一指定群 |

本轮只有第4条 `NATIVE-CAL-004` 用了 UI 校准；第5条实际发送和两条接收验收均无 UI 操作。接收没有强制合并 WAL，也没有忽略校验后恢复页面。原生发送的真实 @ 已获用户明确确认；不是仅凭显示文本出现“@昵称”判断。

## 无界面发送怎样实现

1. 核对当前客户端精确 SHA256/架构，读取已验证的 owner/getter/service/dispatch，避免复用过期服务地址。
2. 构造自己的 `micromsg.SendMsgRequestNew`，通过客户端 New + ParseFromArray 填充文本和真实提及 XML。
3. 把请求交给客户端发送服务，由其复制请求、创建任务并进入 Mars 队列。调用来自工作线程，不依赖窗口、焦点、分辨率、鼠标或键盘。
4. 自建 C 回调库接收任务结果，在任务被销毁前编码响应，核对服务器返回；回调库用 `RTLD_NODELETE` 保留，避免脚本卸载导致异步函数地址悬空。

`NATIVE-005` 本次观察为 **406ms**，包含200ms轮询粒度，不是精确网络延迟，也不是长期性能承诺。taskId=572；完成回调执行1次、销毁1次、存活回调归0。客户端 PID25021 保持登录，未再次崩溃。

此前不发送的对象验证也通过：188 bytes 请求可解析、深复制，释放源对象后副本编码逐字节一致；截断输入被拒。回调九槽的复制、类型查询、调用和释放在独立 ARM 进程验证；异步状态使用互斥锁保护。

## 无界面接收怎样实现

[receive_probe.py](linux/receive_probe.py) 只检查允许群的消息表，只输出 `RECV-001/002`。先复制数据库与 WAL 到临时目录，再由标准 SQLCipher 读取并解压字段；消息 sender、server_id、source XML 用于判定非自己发送和结构化 @。不对活跃微信数据库建立可能重建 SHM 的普通只读连接。

两条入站在探针启动前已经到达，因此**本次不能推算接收延迟**。尚未证明持续监听的完整性；临时副本的读前/读后变化检查也不是正式的事务一致性协议。低延迟方向继续研究 `AddMsg` / `NewSyncResponse` 原生事件；其静态地址不能视为已动态验收。

## 明确的限制

- 仍需要登录的官方 Linux 客户端及其运行环境。消息 I/O 无点击，不等于无客户端或纯协议。扫码、登录恢复仍需要手机配合。
- 当前固定 **Linux ARM64 微信4.1.1.8**，BuildID `9a3558be209dfcf1b85d6ec18bf029c7f97ccb61`。升级或 x86_64 文件不能沿用地址；原生 Windows 客户端、Intel Windows Docker 环境尚未实测。
- 已在 Mac Docker 中运行。Mac 原生客户端路线仍待适配及独立账号环境；本轮没有改动正常 Mac 微信、SIP 或辅助功能权限。
- 当前发送直接进入底层网络任务，未实现高层本地发送记录的插入/状态更新。收件侧已确认消息，但不能保证发送端 UI/本地历史同步出现该条；正式适配需处理业务层记录和幂等。
- 同名成员、改名、个人微信成员 @、引用回复解析、断线重连、重启补读、长时间漏收/重复/乱序统计仍未验收。用户本轮只要求 @ 指定企微成员；没有扩大测试收件人。
- 当前群含个人微信与企业微信成员；创建者身份未独立核实，不以 `@chatroom` 后缀推断创建者类型。
- 崩溃前第3条 `NATIVE-TRACE-003` 的服务器结果仍未知，不自动重发。已确认收到的第2条在恢复后本地库缺失，说明历史恢复/数据完整性仍需要专门验证。恢复后 WAL 样本是重置残尾，不能继续把它称为定制校验算法。[WAL分析](linux-wal-compatibility.md)
