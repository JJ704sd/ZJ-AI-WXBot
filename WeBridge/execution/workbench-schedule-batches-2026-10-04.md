# Windows 工作台批量定时配置

本轮补齐统一模板和按会话配置的批量创建入口。先选择已勾选读取的会话及已保存模板，设置共同的执行日、北京时间和发送窗口，查看每个目标的完整正文，再一次确认创建并启用整批任务。

## 使用与配置边界

定时任务页的“批量定时”支持每批 1～300 个会话。名称相同的会话仍按独立 ID 选择，搜索只改变当前显示的候选，不清空已选择的其他会话。候选包含当前有效、已勾选读取的群及私聊。

正文从服务端保存的模板版本及每个会话的变量或完整覆盖正文生成。缺失变量、空覆盖、无效读取范围或已存在相同的启用／暂停计划都会阻止整批创建；有问题的目标不会被静默跳过。可以从预览进入指定会话的模板配置，保存后重新读取模板版本、生成整批预览。

每日、按星期及一次性任务共享一个日历和执行窗口；每个任务冻结本次确认的完整正文。模板后续修改不影响旧任务，日期变量不会自动更新。会话、名称、正文、模板版本、数据源绑定或首个执行时间变化后，原预览不能创建，需重新核对。

当前账号最多保留 500 条本机定时记录，计入已结束和已取消记录。预览显示现有记录、本批条数及上限。相同目标、正文和日历的启用或暂停计划不能重复创建；其他不同规格的已有计划继续保留，页面显示记录数供核对。本轮没有增加跨所有任务的“每群每天只执行一次”约束。

## 创建与结果核对

预览只读取本机状态，不调用 Hook、不创建任务、不发送消息。确认创建只进行一次 Hook 状态探测，不调用发送接口；探测期间不持有数据源、订阅或引擎锁，返回后重新核对完整预览，再在同一个 SQLite 事务内保存全部任务和批次回执。任何一项校验失败或写入失败均不留下部分任务。

批次请求 ID 与规范化的规格及预览摘要绑定。成功响应丢失时，页面保留原请求和规格，提供“重试核对本批结果”，不会自动重试或换新 ID 创建。相同请求返回原批任务的当前状态，不新增、不恢复已暂停或取消的任务。成功后即使模板被删除、首次执行时间已过或 Hook 离线，也可用原请求核对；同 ID 改规格返回冲突。

## 接口与存储

| 接口 | 内容 |
| --- | --- |
| `POST /api/jobs/batch/preview` | 批量渲染及检查，返回逐会话正文、问题、数量和预览摘要 |
| `POST /api/jobs/batch` | 核对摘要，整批创建并返回批次与任务；原请求重放返回当前状态 |

两者输入为 `{account,templateId,templateVersion,groupIds,mode,clock,at,windowMinutes}`，仅每周模式增加 `weekdays`。创建另带 `requestId`、`previewDigest`，客户端不提交展开后的各群正文或数据源路径。批次冲突返回 HTTP 409 和 `batch_conflict`，模板版本冲突返回 409 和 `template_conflict`。

两个批量接口及既有模板接口允许最多 256 KiB JSON；其余接口仍为 32 KiB。沿用 Host、Origin 和 CSRF 校验。批次回执保存在原 `windows-schedules.sqlite` 的 `schedule_batches` 表，与普通任务在同一事务提交；不保存预览草稿，不改变既有任务 ID 或重启暂停规则。能力声明为 `runtime.capabilities.scheduleBatches`，旧服务和 Demo 隐藏入口。

## 验证范围

验证使用临时 SQLite、合成账号、录制 Hook 替身及全部业务接口被模拟的 Chrome 页面。不修改真实任务或配置，不重启实际工作台，不发送真实微信消息。

完整 Python 回归 **516 项通过、无跳过**，耗时 172.340 秒，使用 Anaconda Python 并将 `ResourceWarning` 作为错误。日志为 `.runtime/workbench-schedule-batches-20261004-tests.log`。批量核心测试 11 项，独立 HTTP 5 项及业务验收 7 项均包含在完整回归中。

300 会话验收使用真实合成副本和 SQLite，覆盖同名群、混合群和私聊，各目标保留自己的变量或覆盖正文；预览没有 Hook 调用、任务、执行记录或发送草稿，创建只有一次状态 GET。第 3 条任务 INSERT 的触发器故障使任务和回执全部回滚，移除故障后原请求仍能成功创建；并发同请求只保存一个批次，另线程在状态 GET 期间能取得数据源、订阅和引擎锁。修改模板、读取范围、来源或跨过首期时间均拒绝整批创建；写入过程跨过首期时间也回滚。

13 组 Node 界面检查通过，新增批量检查 28 项。独立审查用失败反例发现，无关新会话到来会关闭批量窗口并清空选择；现已仅按实际所选目标检查变化，无关候选更新保留草稿和预览，选中目标改名使预览失效但保留合法选择。模板保存及原请求 ID 核对共用已有契约，没有增加对所有会话变化的整批重置。

Chrome 新批量检查 34 项及既有模板 33 项、执行窗口 30 项、每周计划 28 项、批量暂停 36 项全部通过，共 **161 项**。接口全部模拟，覆盖缺失变量修复、模板版本、容量和重复计划阻止、响应丢失后的原请求核对、取消／暂停状态保留、晚响应隔离和旧服务／Demo。日志为 `.runtime/schedule-batch-browser-20261004.log`、`.runtime/batch-regression-{schedule_template,schedule_window,weekly_schedule,schedule_pause}-20261004.log`。

浏览器初次检查复现了模板窗口 `close` 事件尚未异步派发、诊断就提前核对的等待错误；诊断现等待关闭回调消费与版本重读结束，保留版本、选择和旧预览失效的三项断言。未用放宽断言代替核对。

已查看 `output/playwright/schedule-batch-{desktop,mobile,mobile-actions}.png`；正文、模板选择器、窗口输入和最后确认按钮通过边界及 `elementFromPoint` 命中检查，390 像素宽度无横向溢出、正文不受底栏遮挡。

300 个合成会话的配置验收不代表真实 300 群持续运行；普通文本批量定时不替代真实原生 @、批准资料回复或负责人接收端确认。发布代码不会自动加载到正在运行的旧进程；本轮未重启实际工作台。
