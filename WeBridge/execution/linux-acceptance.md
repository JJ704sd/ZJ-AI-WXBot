**后续更新：**本文件保留最初 UI 备用验证及崩溃过程；随后已完成无UI原生发送/真实@和入站普通消息/被@验收，最新结论见 [Linux原生双向验收](linux-native-acceptance.md)。

- 首次发送两条已授权编号消息：`[接入测试] LINUX-001 普通文本验证。`，以及 `[接入测试] LINUX-002 企业成员真实提及验证。` 并通过原生成员菜单选择陈佳豪。之后另尝试一条 `NATIVE-TRACE-003` 校准消息，详情见末节。

## 为什么降为备用方案

当前发送依赖虚拟桌面、输入框和成员菜单。固定容器分辨率、使用辅助功能控件和发送前目标检查能减少坐标误差，但仍依赖焦点、弹窗及客户端 UI，不能满足用户优先协议/内部接口的偏好。用户已明确要求保留它为备用、继续探索更好方案。

实际发现的障碍：

1. `agent-wechat` 的 `chat-select.py` 在当前 BuildID 上明确返回 Unknown BuildID。本轮用辅助功能树定位已授权群绕过该依赖，没有伪造版本或套用旧偏移。
2. 容器预装 Frida 17.17.0 在 Python 3.10 下导入 `typing.NotRequired` 失败。仅在探针进程内引用 `typing_extensions.NotRequired` 后，**只读附加已成功**；没有修改系统包，也没有调用内部发送地址。
3. 消息 API 对仍在 WAL 中的新消息返回旧结果。现场第一条记录可经原接口读取；第二条界面已发送、收件方已收到，但普通只读 SQLCipher 与 `immutable=1` 查询均仍只有第一条。WAL header 校验正常、标准 frame 校验不匹配。在临时副本合并同一 salt 的已提交页后，SQLCipher `integrity_check=ok`，可读到第二条及真实 @ 元数据。

第 3 项说明当前读库路径不能直接承担实时同步。临时合并仅用于诊断取证，尚未解释 frame 校验差异，也不保证并发写入下的一致快照；不把它包装成生产同步实现。没有主动写原数据库正文；但 SQLite 普通只读连接仍可能重建 `-shm`，不能据此声称所有旁文件均未受影响。诊断脚本现已禁止对活跃微信库使用这种模式，WAL 查询只针对临时副本。下一步优先匹配客户端的 WCDB 读法或消息事件 Hook，再验证接收延迟与完整性。[SQLite WAL 格式](https://www.sqlite.org/walformat.html)、[腾讯 WCDB](https://github.com/Tencent/wcdb)

## 当前主线

1. **Linux 内部接口**：定位当前 ELF 的文本任务、序列化和收包函数，先只读观察、核对 ABI，再考虑调用。保留版本/BuildID门槛；不将静态地址候选视为收发成功。
2. **可重建协议核心**：验证公开 Go 协议代码在 Linux ARM64 的实际构建及登录前握手；独立于当前已登录客户端，不自动扫码登录。
3. **Mac 内部接口**：旧官方包已精确匹配 Classic；新版布局变化见 [Mac ABI 报告](mac-req2buf-abi.md)。需要适配和真正独立的运行环境，不能只复制 App 就认为账号数据已隔离。

## 原生调用观察与崩溃记录

为了关联静态函数与指定群实际发送，运行了 55 秒观察型 Hook，随后通过客户端发送一条 `[接入测试] NATIVE-TRACE-003 接口定位验证。` 并选择同一授权企微成员。观察器没有主动调用发送函数或改写参数。

动态观察确认：`0x4852f8c` 生成含该成员 `@openim` ID 的 `atuserlist`；`0x4f62668` 和 `0x4f65f78` 的输入对象可追到指定群 ID；`0x6b5c7fc` 收到 `newsendmsg` 任务，CGI 字符串对象位于 Task+0x18。这将静态候选和实际混合群发送连接起来，但仍不是无界面主动发送成功。

观察期间客户端发生 SIGSEGV 并自动重启。crashpad 记录线程94、fault address 0x8；ARM64 context 的 PC 对应 `libfrida-agent-raw.so+0x37690c`，LR 为该模块+0x376908。宽泛指针读取是重点嫌疑，尚未通过独立复现确定根因。初版观察器已停止；源码补充映射边界检查，但修订版尚未实测，也不能宣布已修复。第三条的服务器接收和提醒未验收，不自动重发。

用户已完成手机确认，API 核实恢复为 `logged_in`，微信进程 PID25021。正常 Mac 微信未受该容器崩溃影响。私有观察证据保存于 `.runtime/linux-native-observation.json`；后续应缩小到已确认对象布局，避免扫描不明参数指针。

修订观察器已去除全部未知参数/指针扫描。字符串读取先验证映射和完整范围；6个边界用例在独立无账号进程通过。随后在测试客户端挂钩15秒，不触发发送，正常卸载，进程与登录状态保持正常。这仅证明一次空闲附加/卸载，不代表发送负载下的稳定性已通过。
