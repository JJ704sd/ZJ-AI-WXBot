## 重大功能：执行记录中心

侧栏新增“执行记录”，汇总当前账号已勾选会话的手动发送、自动回复和定时任务执行记录，支持按来源、待核对 / 异常状态、会话及正文关键词筛选，并可跳回会话。最多显示最近 200 条；筛选仅作用于已加载记录。记录页打开时约每 10 秒刷新，隐藏网页不查询。

新增只读 `GET /api/execution-history?account=...`：校验当前账号，在数据源锁与 Engine 锁内取数；数据库使用 SQLite `mode=ro`，缺失历史文件不会创建。只返回白名单展示字段，不返回源目录、本人标识、原生绑定、密钥、正文哈希或基线消息 ID。自动任务关联草稿合并为一条执行记录；可用时采用草稿最新状态。旧回复没有正文快照时明确标注缺失，不能用当前规则补造历史正文。

切换账号、模式、数据源或读取范围时清空历史列表，迟到响应不能回填旧范围。结果未知只展示，不提供重发；已提交、服务器接受及本地记录仍明确收件端待确认。查询不触发 Hook 探测、消息读取、取钥、发送或自动回执核验。若此前未核验本地记录，历史页不会自行核验或声称有回执。

新增 `test_execution_history.py` 5 项覆盖账号与会话隔离、合并去重、白名单、缺失回复快照、记录上限、读取范围撤销、只读数据库与 HTTP 入口。`check_execution_controls.cjs` 验证账号切换丢弃迟到响应、来源 / 状态 / 关键词筛选及保留无变化 DOM。两份前端合成检查、JS 语法及 `git diff --check` 通过。

## 历史查询范围扩展

聊天消息与执行记录新增 200 / 500 / 1000 / 2000 条范围选择，默认仍为 200 条。消息读取通过 HTTP 将范围传递至数据库 Adapter，保持同一账号及已勾选会话边界；执行记录同步扩大各来源只读查询范围，演示 / Linux 工作台执行记录也不再被 Store 的旧 100 条接口截断。API 校验 1 至 2000 的整数，拒绝无界请求。

扩大范围仅查询现有本地副本和工作台运行记录，不同步微信未保存的历史，不取钥或扩大会话授权。两处搜索均只覆盖当前已加载记录；尚未实现全库搜索或超过 2000 条的分页查询。定时任务卡片仍显示每任务最近 10 条摘要，更早执行结果在记录中心按扩大后的范围查看。

聊天范围切换只更新消息列表，保留手动草稿及未保存的回复规则；会话切换后的迟到结果不回填。执行范围变更会清空旧结果，丢弃旧范围的迟到响应。
