本地个微解析工具的 Windows 迁移检查
检查日期：2026-10-16

本文件记录v3历史检查。图片密钥绝对路径问题已在v4修复，当前结果及Skill能力见 offline-chat-portable-v4-2026-10-16.md；下文保留当时证据。

检查结论

当前桌面 EXE 可以免安装运行，已在本机 Windows 10 x64 的仓库外位置完成隔离迁移验证，不需要用户安装 Python、Tcl/Tk、Pillow、Docker、WorkBuddy、数据库服务或网页工作台。

首次解析仍依赖所选账号的数据副本与匹配的已有数据库密钥；加密图片还需要对应图片密钥及本地媒体文件。没有密钥的新电脑，目前不能只双击 EXE 就读出加密聊天记录。另发现一个已实测的迁移问题：图片密钥文件绑定原数据目录的绝对路径，移动后须处理映射，否则文字可以成功解析、图片却不可用。

因此，当前结论是“程序运行库具备便携性，数据接入仍需首次配置，图片路径迁移尚需完善”。没有另一台独立 Windows 计算机的实际验收证据，不能据本机隔离测试承诺所有 Windows 电脑、所有微信版本和所有媒体都能正常解析。

二、环境与输入依赖

1. 便携桌面 EXE

已内置 Python 3.14.6、SQLite、Tcl/Tk、Pillow、cryptography、zstandard 和必要的本地动态库。检查到 82 个 DLL/PYD 文件，包含 VCRUNTIME140.dll、VCRUNTIME140_1.dll、python314.dll、tcl86t.dll、tk86t.dll。剩余导入为 Windows 系统库。

EXE 架构为 AMD64/x64。Python 3.14 官方支持 Windows 10 及以后版本，因此本包应以 Windows 10/11 x64 为部署目标。Windows 7/8、32位系统不属于本包支持范围；Windows ARM64、Windows Server 和另一台 Windows 11 实机没有在本次验收。

程序清单为 asInvoker，没有要求提升管理员权限。普通用户完整运行仍需在目标机器验证文件权限与策略；本次不是独立标准用户账号验收。程序未数字签名，另一台机器的应用执行策略未验证；本次没有修改任何系统安全设置。

单文件程序运行时会在 TEMP 解出运行库，支持文件未压缩合计约 52.9 MB。TEMP 必须可写，程序旁的 local-chat-data 也必须可写；副本、阅读缓存及导出会额外占用磁盘空间，随聊天和媒体量增加。不要把程序的数据目录放在微信账号目录内。

2. 原始 Python 脚本与仓库启动入口

直接运行 scripts/local_chat.py / scripts/local_chat_app.py 仍需 Python 及实际使用的依赖。加密库需要 cryptography，压缩正文需要 zstandard；桌面版还需要 Tk 和 Pillow。

local-chat.cmd 有 Python 回退路径。根目录“打开本地聊天解析.cmd”只定位仓库 build 目录里的程序，不能只复制这一个 CMD 到新电脑。发给其他电脑使用的入口是便携 ZIP 解压后的“本地聊天解析.exe”。

3. 数据、密钥及本人身份

支持的是当前适配的 Windows 微信 4.x db_storage 结构，不等于所有 4.x schema 都已验收；微信 3.x、手机备份、macOS 数据和企业微信数据库没有由此获得支持。

加密数据需要与这份数据库相匹配的已有密钥文件。数据库按 salt 选钥、逐页校验并验证 SQLite 完整性，只有复制密文文件不能读取。当前程序不自动获取进程密钥，也不依赖另开工作台来取钥。新机器上重新产生的数据库必须重新确认密钥，不能仅凭账号相同沿用旧密钥。

区分“自己/对方”还需要明确的本人微信 ID；未提供时保留未知，不会从账号目录名猜测。

图片/附件需保留同一账号的媒体目录及索引，例如 db_storage、msg、相关 cache 等布局。只带数据库时，正文可读不代表媒体已带齐；数据库密钥也不能代替图片密钥。未缓存原件不会凭空恢复。

4. 查看器依赖

图片预览、放大及转发层级由程序内置组件完成。PDF、Excel、PPT 等文件的提取和校验不需要 Office；点击“打开附件”调用系统默认程序，实际阅读仍需电脑已有相应查看器。视频播放同样需要适配的本机播放器。语音原始编码、WXGF 等未完整支持的内容不能按普通图片/文本承诺效果；表情不作为本次业务判断的必需项。

三、实际执行的隔离迁移验证

使用同一个已交付 EXE，复制到仓库外的临时中文和空格目录；从空白工作目录启动。对子进程清除 PYTHONPATH、PYTHONHOME、VIRTUAL_ENV、TCL_LIBRARY、TK_LIBRARY，将 PATH 限定为 Windows 系统目录，并使用隔离的 USERPROFILE、APPDATA、LOCALAPPDATA、TEMP/TMP。没有工作台配置，也没有把 Python 或构建依赖放到旁边。

输入为当前已授权账号的 6 个加密业务/媒体索引数据库、6 个 WAL，以及 589 个媒体文件（52,677,543 字节）的独立复制品。只取已有密钥中匹配本批数据库 salt 和所选账号的条目。原始数据与原始配置没有改动。

用例A：只有 EXE、没有配置和数据密钥。
结果：原生窗口创建成功，进程正常退出自检，提示“首次使用：选择本机数据目录；加密数据还需选择已有密钥文件”。这证明程序能启动，不能记为聊天解析成功。此自检在首次配置状态退出，没有通过人工点击验收首次设置弹窗。

用例B：选择迁移后的加密数据，但不给数据库密钥。
结果：窗口启动成功，明确提示缺少匹配密钥，没有假报成功或发布部分聊天数据。

用例C：提供匹配数据库密钥，但图片密钥保留旧 sourceRoot 绑定。
结果：识别3个群；目标群285条全部解码，业务阅读264条；7个转发结构、8个引用来源及5个附件打开回调通过；图片显示0项。媒体统计为5项可用、53项未取得。

用例D：只修改临时图片密钥副本的 sourceRoot，使其指向同一批迁移数据的新 db_storage 目录。
结果：识别3个群；目标群285条全部解码，原始源列与已有导出逐条一致；业务阅读264条；图片显示19项、嵌套图片1项、转发结构7个、引用来源8个、图片放大窗口1个、附件打开回调5个，原生控件错误列表为空。

媒体统计恢复为原件10项、缩略图14项、未取得34项。其中表情21项不强求，业务图片仍有13项缺原件。计数按媒体引用，不代表不同文件。没有把自检中捕获到的附件打开回调当作5个外部查看器的人工渲染验收。

用例C与D仅改变临时图片密钥中的路径映射，明确支持“绝对路径绑定导致迁移后图片失效”这一因果判断。修正测试副本不是修改程序，也没有使现有分发包自动具备路径迁移能力。

测试结束后，仓库外的临时数据、密钥、隔离用户目录与程序副本已删除；原始数据库、原始密钥和原始设置的摘要不变。

补充检查：42项相关现有测试通过；运行身份检查扫描77个文件、0问题；git diff --check 无错误。本次没有创建代码提交或发布新包。

四、影响其他电脑使用的明确问题

P1：没有已有匹配密钥时，不能直接完成新机器的加密数据库解析。
这是当前输入前提，不是缺一个可安装运行库。交付前须明确密钥如何由有权访问数据的人准备；不能把“免安装”说明成“无需密钥”。
出处：web_mvp/database_snapshot.py 的 _load_keys、_Cipher、prepare_snapshot；scripts/local_chat_app.py:432。

P1：图片密钥中的 sourceRoot 为绝对路径绑定，迁移后19项可显示图片在本次样本中降为0项。
建议：增加有明确账号/副本校验的迁移或重新绑定入口；先验证数据归属及解码完整性，再保存新的路径映射，保留旧配置，不直接放宽到任意账号共享密钥。
出处：web_mvp/windows_media.py:138，尤其 sourceRoot 与密钥记录路径的相等校验。

P2：保存的 sourceRoot、keyFile、imageKeyFile 都是绝对路径。
把程序目录复制到另一台电脑，或用户名、盘符、数据位置改变后，需要重新选择数据与密钥。不会自动遍历磁盘找钥或悄悄切换账号。
出处：web_mvp/offline_desktop.py:18、:78；scripts/local_chat_app.py:432。

P2：自动发现只检查用户 Documents 下的 xwechat_files 和 WeChat Files。
自定义目录、OneDrive 重定向文档位置及其他布局不保证被自动发现，但可通过数据设置手动选目录。发现目录也不等于已获得解密密钥或识别当前账号。
出处：web_mvp/offline_chat.py:83。

P2：独立明文库与原媒体分开存放时，桌面界面没有单独的媒体根目录字段。
按当前窗口契约，需准备支持的同账号目录布局；CLI 可通过 --media-root 指定媒体目录。不能承诺任意明文备份文件夹直接带出全部媒体。
出处：scripts/local_chat_app.py:432；scripts/local_chat.py:137；web_mvp/windows_media.py:158。

P2：没有另一台干净 Windows、标准用户及其他微信版本的独立验收。
本机隔离环境测试排除了仓库路径、Python PATH 和已有工作台的必需性；没有排除目标机器系统策略、权限差异、不同操作系统版本或不同微信 schema 的影响。

五、分发及验收建议

当前可分发的是便携 EXE 包，使用者解压后启动；首次选择本人有权访问的数据、匹配数据库密钥及可选图片密钥。通用包不携带任何真实数据或密钥。

正式宣称跨机一键可用前，先完善图片路径迁移与首次配置说明，再在另一台 Windows 10/11 x64、普通用户、无 Python/WorkBuddy/工作台的电脑上完成：启动、选择真实4.x数据、解密列群、正文/双方/@、图片、附件、引用及嵌套转发复测；分别记录原件、缩略图和缺失项。

测试另一份账号数据时，重新核对该账号的密钥、本人ID与库结构；不将当前群样本结果转记给其他账号。现阶段不承诺未缓存原图、所有表情、完整语音/视频理解或所有历史数据恢复。
