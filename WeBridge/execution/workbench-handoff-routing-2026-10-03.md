# Windows 人工待办的群负责人配置（2026-10-03）

业务要求为各群设置负责人，无负责人时进入统一队列。此前工作台只能领取待办时逐条输入负责人。本轮增加按群保存默认负责人、新待办分派，以及负责人和未分派筛选，沿用已有本机待办和处理记录。

后续已新增独立配置的 [负责人私聊通知](workbench-handoff-notifications-2026-10-03.md)。负责人标签不代替实际收件人 ID；修改标签会关闭相关通知配置并取消未开始提交的通知，需核对接收私聊后重新启用。本页下方保留原负责人分派轮次的验证记录。

## 操作和分派语义

在“人工待办”打开“群负责人”，选择当前已勾选读取的群，填写本机负责人标签并保存；清空标签再保存即取消该群的默认分派。群按稳定 ID 区分，同名群不会共享配置。负责人标签最多 80 个字符，须为单行文本；同名人员可以用部门等信息区分。

标签只表示本机处理责任，不是微信收件人标识，也不用于身份认证、发送消息或真实 @。设置默认负责人不等于已经通知本人，页面继续明确显示“未通知负责人”。

启用“转人工待办”的群收到符合现有规则的新结构化 @ 时，入队事务读取该群的默认标签，复制到任务及创建记录。任务仍为待领取；有标签显示“已分派 · 待领取”，没有标签则保留在未分派队列。处理人仍须明确领取才进入“处理中”，也可在领取时填写实际负责人。

修改或清除默认标签只影响之后创建的待办。已创建任务、已领取事项及其处理记录保持原负责人；重复入站不会重新分派旧任务。释放和重新打开仍按原约定清空负责人，返回未分派队列，不再自动套用群默认值。

队列可以显示全部负责人、仅未分派或指定标签，按完整标签精确匹配。筛选先于分页；即使群默认标签已改变，旧任务中的负责人仍能被选择。标签选项只来源于当前账号、当前已读取范围中的配置和任务，不显示其他账号或取消读取群的标签。

## 独立配置与并发

负责人配置独立存储，不通过保存自动回复规则来实现。更改负责人不会启停群规则、重建入站基线、重置回复间隔或改变定时任务。已经进入副本、尚未处理的新消息继续按现有入站规则判断，在创建待办时读取当时生效的默认负责人。

设置按版本检查并发修改：未配置版本为 0，保存后版本递增；清空配置保留记录及版本，避免旧窗口恢复已清除的负责人。已有配置仅在版本相同且内容不变时可无变更返回，旧版本不能自动覆盖新值。冲突返回 409，页面保留草稿，用户可明确重新加载后核对。

轮询不覆盖正在编辑的负责人。账号或读取范围变化时关闭旧详情；切换配置群后，迟到请求不能恢复另一群的草稿或保存反馈。

## 存储与接口

新增 `handoff_routes` 表位于已有 `windows-auto-reply.sqlite`，主键为账号及群 ID。旧待办、旧处理记录和群规则不迁移或回填负责人。重启保留配置；原有“重启后规则暂停，需明确启用”的约定不变。

| 接口 | 数据与作用 |
|---|---|
| `GET /api/handoffs/routing?account=…` | 返回当前可配置群及各自负责人、版本和修改时间 |
| `POST /api/handoffs/routing` | 保存 `{account,groupId,version,owner}`，返回保存后的配置 |
| `GET /api/handoffs` | 增加 `ownerFilter=all\|unassigned\|owner` 和 `owner` 参数；原筛选与分页参数不变 |

配置列表返回 `{routes:[{groupId,groupName,owner,version,updatedAt}]}`。未配置项使用空标签、版本 0、修改时间 `null`。待办列表新增 `owners` 标签列表；使用 `ownerFilter=owner` 时须提供非空 `owner`。翻页游标绑定负责人筛选，不能用于另一负责人的列表。

接口沿用本机 Host、Origin、CSRF、当前数据源账号与读取范围检查。功能不需要 Hook，但仍需当前数据库副本可用。配置目标限定为现有待办规则支持的已读取群；本轮不扩大自动入站的群类型范围。功能能力为 `runtime.capabilities.handoffRouting`；旧服务和 Demo 隐藏新增入口，旧客户端省略新筛选参数时保持原列表行为。

## 验证

验证使用临时 SQLite、合成群和消息、录制发送替身及模拟浏览器接口；不修改实际群配置或联系人，不启动真实通知。

完整 Python 回归 456 项通过，无跳过，耗时 125.177 秒，包含原 Hook、定时任务、模板、入站和待办测试；日志为 `.runtime/workbench-handoff-routing-20261003-tests.log`。

关键验收包括两个同名群分别分派、未处理入站不因修改负责人丢失、任务与创建记录的负责人一致、默认变化和重启持久化、释放／重新打开回到未分派、精确筛选后分页、过期配置冲突、账号及读取范围隔离，以及页面草稿和迟到响应保护。

新增 10 项配置与队列单测、2 项合成入站事务测试、3 项 HTTP 集成测试。HTTP 使用真实 Adapter、服务与临时数据库，把两个同名群的结构化 @ 分别分派到正确标签；在副本更新后、消息尚未处理时更改负责人，直接核对 `rules` 和 `baselines` 未变，随后两条待办均正常建立。配置、列表、领取和释放均未调用真实发送接口。
