# 群聊 v43：解密、解析与导出成功路径修复

交付：桌面 v43、个微/企微群聊 Skill 1.29.0，2026-10-23。基于 v42，私聊现有交付包保持 1.7.0。所有开发与验收均使用临时合成数据。

## 已完成的修复

| 阶段 | 原失败路径 | v43 行为 |
| --- | --- | --- |
| 个微取钥 | 所选语音库未传入取钥范围；明密混合库被整体拒绝 | `includeVoice` 贯穿 GUI、任务、CLI 和 worker；仅匹配密文部分，每个所需库都须验证 |
| 企微取钥 | 要求同一候选匹配全部库，不同库使用不同密钥时失败 | 逐库匹配和复核，保留当前进程归属与读取预算约束，部分匹配不落盘 |
| 配置与恢复 | 加载或导入失败前清空旧复核；工作台回退遗留旧状态 | 候选来源先验证，设置和进度切换成功后才安装；失败保留原解析、确认和导出 |
| 错误处理 | 无关失效密钥阻断明文；磁盘或权限错误误转取钥 | 明文可忽略失效密钥引用；通过内部错误类型区分快照 I/O 故障，修正后重试 |
| 消息解析 | 坏 ID、类型、发送人编码、异常时间使整群失败 | 保留原始字段、有效正文、来源位置和异常状态；正常 ID 不变，坏 ID 使用来源行位置引用 |
| 时间与范围 | 企微按全表最大时间决定单位，秒/毫秒混存导致漏行 | 逐行归一化，时间未知记录排在最后并额外保留；复核、报告和分析材料明确不能确认其日期范围 |
| 媒体 | 超大像素图片导致整群失败 | 仅该附件标为不可用并说明原因，不关闭像素限制 |
| 人工入口 | 配置页加载和导入按钮重叠 | 分开显示，真实 Tk 指针命中验证通过 |

异常元数据的提示同时进入 `messages.jsonl`、Markdown、业务阅读、复核警告和宿主分析材料。未知发送人不推断为对方来信。全部原始证据仍以 JSONL/JSON 和来源为准。

v42 的逐群原子发布、人工复核、重启恢复、剩余群重试、清单及跨群分析修复继续保留。没有增加生产依赖，没有迁移设置或检查点格式；新增的消息缺口字段兼容旧导出。原始数据库与历史交付包未改动。

## 数据量与性能边界

10 万条记录、每种查询 3 次、两客户端正常/混合数据，共 36 个样本；仅计 SQLite 查询与流式合并，不计解密、正文解析、媒体和渲染。使用普通 Windows 文件缓存，交替测量。正常结果顺序摘要与 v42 相同。

| 正常场景 | v42 中位数 | v43 首次探测 | v43 复用探测 |
| --- | ---: | ---: | ---: |
| 个微 10 万条 | 0.707 秒 | 0.869 秒 | 0.727 秒 |
| 企微 10 万条 | 0.662 秒 | 0.864 秒 | 0.810 秒 |

混合异常个微从 99,900 条补足到 100,000 条，含 100 条时间未知记录；企微从整批 TypeError 恢复到 100,000 条，含 100 条时间未知记录。这是特定合成场景的修复证据，不能外推真实账号成功率。

首次探测扫描所选表/会话，即使日期范围较窄；固定快照内复用探测结果。正常整数秒或整秒毫秒可保留时间索引路径，异常、混合或含毫秒余数的记录使用 SQLite 规范化与临时排序，没有全量 Python 加载。本轮有额外查询成本，未宣称普遍提速。完整测量见 `group43-parse-benchmark.json`。
