# Windows 定时发送执行窗口（2026-10-03）

业务定时索价要求明确执行窗口。原工作台固定允许计划后 120 秒，并且只在消息副本读取前检查时间；读取、Hook 探测或持久化耗时较长时，仍可能越过截止时间才调用提交接口。本轮同时补齐窗口配置和本机提交前的截止检查。

## 工作台操作与时间语义

Windows 定时任务创建窗口增加“执行窗口”，按整数分钟填写，范围 1～1439，默认 2。窗口从计划时间起算，包含截止时刻；例如 09:00、15 分钟，允许本机在 09:00 至 09:15 提交，超过 09:15 本期跳过。时间仍使用北京时间 UTC+8，不依赖 Windows 当前时区。最长小于 24 小时，避免相邻执行日的窗口重叠。

一次、每日和按星期任务均使用该配置。窗口跨午夜时仍属于计划时刻所在执行日；例如周五 23:59、5 分钟，可截至周六 00:04（含）提交周五该期。错过窗口不补发，不会因扩大窗口而重新发送已经领取或结果未知的旧一期。

任务列表显示每条任务的窗口长度。窗口与目标、正文及执行日一起冻结；调整需取消旧任务后重新创建。暂停和工作台重启仍须明确恢复，只安排未来计划，不借用旧一期尚未结束的窗口。

准备发送期间窗口结束时，本期计划记为错过：一次性任务结束，重复任务继续未来执行日。若发送草稿已经建立，它记录为已过期，并注明执行窗口已结束、未提交。发送请求开始后才返回的成功或未知结果保留其实际状态，不因回包较晚改成错过，也不自动重试。

若处理跨越多个执行日，先完成本期记账并保留下一待处理计划，后续轮询补记中间错过日期，再核对最新一期是否仍在窗口内。例如周一的慢读取拖到周三计划后的第 1 分钟：周一和周二记为错过，周三仍在所配窗口内时可执行一次，不直接跳到周四而漏掉账本。

窗口约束本机调用 Hook 提交接口的时间，不保证原生线程执行、网络传输或收件端收到消息的时间，不能撤回已经开始提交的内容。统一模板与按群变量的后续实现见 [模板与会话配置说明](workbench-schedule-templates-2026-10-03.md)；真实 @ 和批量配置仍是独立待实现或待验收项。

## 接口、持久化和兼容性

沿用 `POST /api/jobs`，可增加 `windowMinutes`。入口只接受整数 1～1439，布尔值、空值、小数、字符串及越界值拒绝；内部时间计算使用已验证的值。任务 DTO 始终返回实际 `windowMinutes`，能力声明新增 `runtime.capabilities.scheduleWindows`，仅安装 Windows 调度器的数据库模式为真。

省略字段与显式传入 `2` 等价，不改变既有任务规格和持久化形式。其他值同时保存在任务和请求规格中；同请求 ID 更改窗口会被拒绝，同规格重试只返回原任务。既有任务只在读取处应用 2 分钟的历史默认值，不批量重写任务或执行账本。

| 组合 | 行为 |
|---|---|
| 新服务读取旧任务和旧请求 | 默认 2 分钟，原 ID、幂等规格及历史保持 |
| 新页面与新服务 | 可配置窗口，响应和卡片显示实际值 |
| 新页面收到无 `scheduleWindows` 能力的服务状态 | 隐藏配置、明确固定 2 分钟，仅发送原请求字段 |
| 任意外部新请求直接发给旧服务 | 不支持；旧服务可能忽略未知字段，调用者须先核验能力 |
| 已保存非默认窗口的运行目录交给旧服务 | 不支持；回退代码不会撤销数据变化，旧服务不能解释新窗口 |

服务与页面应成套更新；本轮不增加并行创建接口或双写迁移层。实际运行目录未作升级、回退或数据迁移。

## 提交边界

调度器以计划时刻加窗口长度得到本期截止时间，通过 `send_automatic` 的服务端 keyword 参数传递，不接收浏览器指定的 deadline，也不把它加入原生协议。发送器先保留既有非 `prepared` 草稿的结果；尚未提交的草稿在取得发送保护锁后和最终提交前检查窗口。

最终检查位于 Hook 探测和 `attempted` 账本提交之后、调用 POST 之前，因此消息读取、准备、探测及 SQLite 等待均不能借早先一次时间检查绕过截止限制。超时保存专用 `schedule_window_expired` 结果，不执行 POST。POST 开始后沿用现有回执与 unknown 处理，不再用截止时间改写已发生的提交事实。
