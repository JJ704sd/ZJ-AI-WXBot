# 微桥 · 微信接入最小验证版

本机入口：<http://127.0.0.1:8787>。Windows 可双击根目录 `start-workbench.cmd` 启动，默认使用 `Database` 模式：复制业务数据库与 WAL，在独立副本上解密、校验和查询，并检测源文件变化。另有 `-Mode Demo` 合成演示及 UIA / OCR 诊断，详见 [Windows 说明](../WINDOWS.md)。各模式的实测记录分别维护。

以下真实登录、接收、发送及附件契约均指 `Live` 模式使用原 Linux 测试客户端的个人微信账号，浏览器只连接本机。原记录中的 Mac 路径、版本和已验证样本是历史实验环境信息，不代表在当前 Windows 主机上重新验收。

## 使用

1. 点击右上角“账号 / 登录”或左下角账号入口；离线时点击“扫码登录 / 刷新二维码”，在手机扫码授权。已连接时可“退出当前账号”。
2. 点击“选择读取群聊”，勾选需要的群或“全选”，然后保存。只有勾选的群持续同步消息；新账号默认不读取任何群。旧版配置迁移时保留已有规则对应的群。左侧再选择当前查看的群，可点“@ 我的”筛选，或“群资料”查看群名、群主和成员。
3. 右侧“发消息”输入文字，按需选择群成员，点击“立即发送”。选择成员会携带真实 @ 标识，仅在正文手打 `@名字` 不等于真实提及。
4. “每天定时发送”选择群、时间、文字和提及成员。按 **Asia/Shanghai（北京时间）** 执行；今天的时间已过则从明天开始。可在“定时任务”停用。
5. “自动回复”填写固定话术、设置间隔，打开开关后点“保存规则”。仅对该群直接 @ 当前账号的新消息回复，并真实 @ 发送者。每群独立配置，新群默认关闭。

发送状态区分等待、发送中、微信服务器已接收、失败和结果未知。成功回执不代表接收端已阅读；结果未知时请先看群聊，系统不自动重发。

同群回复间隔默认 30 秒。在间隔内的新 @ 会跳过，避免连续触发。自己的消息、只 @ 其他人的消息、仅 @ 全体成员的消息及启用前的历史消息不触发。保存关闭会取消尚未提交的自动回复，已经提交的消息不能撤回。

取消读取某群会关闭该群自动回复并取消尚未提交的回复。读取范围与手动发送、每日定时分别配置，因此取消读取不会删除定时任务。网页内退出账号会关闭该账号所有自动回复、取消排队消息；配置与每日计划保留。退出期间不启动发送，重新登录同一账号后每日计划恢复按时间运行，自动回复需重新开启。这里的“退出”不是注销微信账户。

## 图片、视频、文件与聊天记录

- 图片在消息流显示缩略内容，点击可看大图或下载；已验证真实 JPEG、PNG 缓存解码。
- 视频按需加载完整 MP4。优先读取完整缓存；本次验证的企业微信视频可使用消息自带授权从微信官方文件服务器分段下载、解密并校验后播放，无需在 Linux 窗口手动播放。只有封面时明确标注，不提供把 JPG 当成视频的预览/下载入口。真实 6.6 秒 H.264 视频已在网页从头播放到结束，HTTP 分段读取通过。
- 文件显示名称、大小；可下载原文件。PDF 使用随应用附带的 PDF.js 在本机逐页预览，支持翻页；文本文件可直接预览，Office 等其他格式下载后打开。文件内容不上传第三方。
- “群聊”等合并转发卡片可展开多条记录，显示发送者、时间、正文；每层最多 200 条、最多 5 层。记录内图片、视频、文件可尝试读取对应缓存，当前真实验收样本是 4 条文字记录。
- 撤回消息显示微信实际撤回通知。客户端提供目标消息编号时同步移除原附件入口；不能恢复微信已经撤回的内容。

图片与文件仍依赖当前 Linux 微信已下载的缓存。视频额外支持本次已验收的企业微信官方下载方式（`tpvideourl` 指向 `https://wwfile.work.weixin.qq.com`）；其他来源、授权过期或格式不支持时说明原因并提供重试，可先在 Linux 微信下载。**当前未实现通用的原生附件下载接口**。单附件上限 100 MB。部分自定义表情的缓存加密格式尚未适配。企业微信邮件卡片等受权限限制的内容保留原提示，不能由个人微信展开邮件内部附件。

视频官方下载仅在加载该条视频时发生：使用消息自带的 `authkey` 请求头，只允许上述官方 HTTPS 域名和 443 端口，不跟随重定向；校验连续字节范围、大小、AES 解密结果和原消息 MD5，再缓存本机文件。不会把签名地址或凭证返回给网页。此权限已由用户明确授权。

关闭网页不等于停止后台。已保存的每日计划及回复规则继续生效；电脑休眠、Docker/微信离线或后台退出会中断处理。定时调度允许 2 分钟延迟，超过后跳过当次，不补发；发送失败不会自动重试。服务重启将未发出的队列项取消，发送中的项标为结果未知，首次同步也不补回复历史消息。

## 在当前 Mac 启动

先确保 Docker Desktop 已启动、`wechat-lab-linux` 容器运行，再执行：

```sh
cd /Users/neo/Documents/by/WeChat_Agent
sh scripts/start_web_mvp.sh
```

脚本将桥接文件装入已有测试容器，随后启动本机网页服务，不重启或退出微信。重复启动会提示服务已经运行。当前会话已在后台启动服务，日志为 `.runtime/web_mvp/server.log`。

停止后台：

```sh
cd /Users/neo/Documents/by/WeChat_Agent
sh scripts/stop_web_mvp.sh
```

停止网页后台不会停止微信容器。它会停止消息监测和未来调度；已提交微信服务器的发送无法取消。

依赖：Python 3.10+、`websockets` 14–17、Docker CLI，以及已准备好的 Linux ARM64 客户端实验容器。启动脚本优先选用本机已存在的 Codex Python 环境，也可用 `WECHAT_MVP_PYTHON=/path/to/python3` 指定解释器。新环境先安装 `web_mvp/requirements.txt`。

## 实现与边界

- 页面：本地 HTML/CSS/JavaScript，无外部 CDN；后台：Python HTTP 服务和 SQLite 持久化。
- 发送：复用已经验证的 Linux 微信内部接口，动态注入自有回调库取得服务器回执；没有操作聊天窗口，也不是脱离客户端的纯协议。
- 接收：读取临时 DB + WAL 副本，解析发送者和 `atuserlist`。每轮扫描后等待约 2 秒，实际延迟还取决于客户端落库和读取耗时；未实现原生即时事件订阅。
- 登录/退出：对接现有实验容器的登录 WebSocket（强制扫码模式）和退出接口；网页显示二维码及手机授权状态。登录和退出阶段仍依赖上游对客户端界面的处理。
- 真实收发当前适配 **Linux 微信 4.1.1.8 ARM64**，二进制 SHA256 严格锁定；版本变化会阻止原生发送。Mac 通过 Docker 运行此 Linux 客户端；历史实验没有验证原生 Mac、Windows 或 Linux x86_64 收发适配。新增 Windows UI Automation / 本地 OCR 入口仅尝试读取所选可见窗口文字，不等于完整原生消息适配。浏览器页面本身无系统限制。
- 群列表和成员来自本地已同步数据，首次加入的新群可能需先在微信打开并刷新。页面展示每群最多 200 条最近消息；未提供语音解码、历史全量导入或发送引用回复。
- 图片缓存使用当前二进制固定布局，校验 SHA256 后仅对账号对象做有界只读内存读取，解码 V2 DAT；不调用客户端函数、不做全内存扫描。附件数据经摘要校验后保存本机私有缓存，通过账号与读取群范围校验、随机附件 ID 和 HTTP Range 提供给页面。
- PDF 渲染器为本地附带的 `pdfjs-dist 5.6.205`，许可证见 `static/vendor/pdfjs/LICENSE`。没有 CDN 或在线文档转换服务。
- 原生发送可能不写入客户端自己的本地聊天记录，因此页面用本机发送记录补全，并按服务器消息 ID 去重。
- 配置绑定实际微信账号和群 ID；账号切换后不把旧账号任务发送到新账号。
- 仅监听 `127.0.0.1`，检查 Host/Origin 和 CSRF 凭证；不提供局域网访问或多用户账户功能。

私有状态位于 `.runtime/web_mvp/`，包括读取到的消息、附件缓存、配置和发送记录；已有容器凭证位于 `.secrets/`。这些目录已在 `.gitignore` 排除，均不应分享或提交。退出账号或取消读取后无法通过附件接口访问旧数据，但不会删除本机缓存。

## 验证

```sh
python3 -m pip install -r web_mvp/requirements-dev.txt
python3 -m unittest discover -s web_mvp -p 'test_*.py' -v
```

测试使用临时数据库和模拟微信接口，不发送真实消息。33 项测试覆盖账号隔离、消息去重、历史消息不重放、冷却、取消任务、重启恢复、每日调度、读取范围、退出时取消队列、撤回、合并记录、附件访问、视频加密分段下载/解密/完整性校验、完整视频优先于封面、扫码事件过滤以及 HTTP 跨站请求与路径防护。

视频故障的真实复现检查保留在 `web_mvp/diagnostics/check_video.py`，默认指向本次专用测试群与测试视频。运行时会加载对应视频；可通过 `--group` 与 `--message` 指定当前账号已勾选群中的另一条已授权视频。

实际验收记录见 [`execution/web-mvp-acceptance.md`](../execution/web-mvp-acceptance.md)。
