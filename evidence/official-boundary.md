# 混合外部群机器人：腾讯官方能力核验

核验日期：2026-09-12。目标限定为企业微信成员与个人微信成员同在的外部群，持续获得普通群消息，并由机器人在原群主动回复。本文件只记录可行性边界；没有登录账号、进入群聊或发送消息。

## 结论

本次未核验出腾讯官方提供的「混合外部群普通消息持续读取 → AI → 原群无人值守主动发送」完整闭环。不能据此宣称所有技术路径不可行，也不能把支持企微群聊的接口直接判成支持混合外部群。

- 传统群 Webhook：官方产品文档明确外部群不支持配置，不能用于目标群；文档描述的是把告警推送进群，不能推导为监听群消息。
- 新版智能机器人：官方 SDK 已支持 WebSocket 收发、回调、流式回复与主动推送。官方产品接入文档列出单聊与群内 @ 触发。因此「企微机器人只能单向发送」已经不准确。但本次可读取的一手文档未证明智能机器人可加入含个人微信的外部群、接收未 @ 的全部普通消息。此路径不能作为目标已可行的证据。
- 官方 CLI：消息能力明确限定为向机器人最近对话过的会话主动推送，没有在当前 README 中承诺托管普通账号、读取普通账号全部群历史。
- 会话内容存档/会话分析：官方文档证实可以分析内外部群消息；这一事实不附带在外部原群直接发送消息的权限。当前专区版还规定明文在专区内分析，只返回结果，不能把它等同于任意外部 LLM 可读取明文。
- 微信客服：官方确实提供 AI 自动应答接入；其接待窗口是客服会话，不能用该能力证明原混合群里的机器人收发。

## 最小验证该验证什么

针对候选个人微信接入项目，决定可行性的实验仅需：在一个明确含企微与个微的授权测试群里，先观察企微成员和个微成员分别发送的不带 @ 文本，再向模型提供收到的真实消息，并通过同一接入通道回到这个群发送测试文本。收与发都要保留群标识、消息标识和时间证据。

普通个微群或企微内部群的成功不代替本实验；仅导出历史记录或成功调用模型也不代替本实验。收到消息但无法原群发出，应判为分析链路可行、自动回复链路未成立；一轮成功只能证明功能闭环，不证明长期稳定性。
