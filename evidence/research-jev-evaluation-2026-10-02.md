## 2. 修正旧报告的四个容易误用之处

1. **95.70% 输入节省不是“多 Agent 的收益”。** 旧报告从“每条消息都输入 2,000 token”比较到规则筛选、合并、短状态、少量生成，主要是减少无关调用与上下文的假设收益。优化后的单 Agent 也能采用这些机制。正式对照必须保留优化单 Agent，并单独消融 gate、上下文压缩、专家拆分。
2. **“首轮三条对照”应同时控制模型和编排。** 规则＋小模型与规则＋Jev用于比较判定器；一个业务 Agent与多个专家用于比较编排。直接拿不同模型、不同上下文和不同发送权限比较，会把三个变量混在一起。
3. **Jev 账单单位现在已有公开依据。** 可替换旧报告“待核价”的泛称为“已核验公开输入 token 单价；中文实耗与账号账单待验证”。请求数仍影响网络、限流、重试和时延，但不是当前公开价目的直接计费单位。
4. **200 个事项只能做流程起步。** 若其中无需发言的机会只有 100 个，即使 0 次误介入，在独立同分布假设下单侧 95% 上界仍约 2.95%；不能据此声称低误回复。大规模影子观察应另行获得足够的负例分母，并报告群／事项相关性。

## 3. 把“语义判断”与“发言授权”拆成两个确定契约

以下为设计建议。Jev 不拥有 Hook、账号、发送器或权限配置；它只拿代码筛出的最小文本状态。

**代码前置与最终复核字段**：来源完整性、事件 ID、稳定账号与群 ID、真 @ 元数据、本人回显、实时／历史、允许场景、当前接管 owner、租约、状态版本、策略版本、预算、发送账本。程序已知的字段不再问模型。任一硬条件不满足，`allow_send=false`；语义评分不得覆盖该结果。

**轻判定请求的建议状态**：最近新增片段、有效引用原文、2–3 个同群候选事项的短状态、尚未满足的槽位、可用资料版本、从程序读取的人工接管状态。候选数是初始实验参数；候选范围召回另测。缺证据写明 `unknown`，不能用摘要补造附件内容或人员身份。

| 问题 | 建议 primitive／答案空间 | 代码如何使用 |
| --- | --- | --- |
| 片段是否提出需要处理的业务请求 | Noul；明确排除转述、引用旧请求、已取消事项 | 低／中概率进入 TRACK、补上下文或人工；不直接放行发送 |
| 片段最可能属于哪个候选事项 | Choice：候选 case ID＋NEW＋UNRESOLVED；若片段含多个独立请求先标 MULTI | 只选“相对最像”仍可能没有任何有效匹配，须保留 UNRESOLVED 并检查关联证据 |
| 片段是否给现有事实作更正／取消 | Noul；明确命名目标事件或槽位 | 高概率只是更新候选；确定 target 后由 reducer 更新版本并废弃旧草稿 |
| 现有证据是否足以回答资料请求 | Noul；区分已发送、可读取、已读取且版本有效 | 缺资料产生待办或澄清；不让模型用常识补业务事实 |
| 请求属于哪类意图 | Choice：资料、售后、价格、订单、闲聊、其他、无法确定 | 映射业务路由；价格／交期等受限类别仍按既有策略走人工 |
| 是否明确要求人工处理／暂停机器人 | Noul；识别自然语言诉求，不等同已验证操作员命令 | 创建待办／暂停建议；明确 UI 接管事件直接生效，无需此模型问题 |
| 紧急性 | Score：不紧急、需当日跟进、需立即人工关注（仅假设 rubric） | 影响人工队列优先级；Score 不用于计算精确金额或期限 |

不要为了降低请求数把所有群放入一个共享 state。批问题优化只限同权限范围、同事项或可隔离候选集；两家客户的数据不会因为模型只输出 Choice 就失去泄露风险。

一个消息可包含多个事项，例如“B 型资料再发一下，A 型那单先别处理”。单一 intent 标签会漏掉一半。建议先识别 MULTI，再以原文证据跨度形成两个任务候选；生成式抽取器或人工可以提出候选，但 reducer 必须验证群、参与人、目标事项和证据跨度。对分句不可靠的输入保留整段并转人工，不以省 token 为由强行切断否定范围。

## 4. 人工接管、撤回和竞争条件必须做时序回放

以下是**假设合成序列**，不是本项目真实聊天。测试时每一步只能看到当时已观察到的事件；不得先把最终完整对话给模型。

| 回放步骤 | 观察到的事件 | 期望状态／断言 |
| --- | --- | --- |
| t0 | 客户甲真 @ 机器人请求 B 型资料 | case-1 可进入已批准资料场景；仅生成版本 v1 草稿 |
| t1 | 客户乙说“A 型那单先别处理”，无引用 | 不并入 case-1；出现取消候选 case-2 或 unresolved；不取消甲的请求 |
| t2 | 业务员通过工作台接管 case-1 | owner=human，state_version 增加；v1 草稿失效；无需再问模型 |
| t3 | 旧模型调用返回“可以发资料” | 因引用旧 state_version，拒绝进入发送队列；记录 stale_decision |
| t4 | 客户甲撤回 t0 | 给 t0 加撤回事实，case-1 证据无效；摘要／检索结果与待发草稿同步失效 |
| t5 | 客户甲改为“刚才说错，是 C 型” | 新事实，不能恢复 B 型草稿；仍在人工接管中；仅更新跟踪与人工待办 |
| t6 | 人工释放接管，同时有重复 t5 到达 | 重新读最新状态及政策；重复事件不产生第二任务；释放不等于允许恢复旧草稿 |

另做两组顺序：撤回先于原消息到达、接管先于旧草稿提交。撤回目标暂未到达时先保留 tombstone；迟到原消息不能重新触发。若外部消息提交已经发生，再发生接管／撤回，不能声称“保证未发”；记录实际提交先后和剩余风险。本地事务可序列化本地状态与 outbox，无法原子化远端平台与本地数据库。

为避免测试在完美时序上通过，至少故障注入：重复、乱序、消费重启、模型超时、429／529、资料过期、群或账号切换、API 响应缺字段、模型别名变更。超时和预算耗尽仍保留采集与待办；不得切换到权限更宽的模型或发送通道。

## 5. 公平对照矩阵与成本账本

以下各组使用同一原始事件序列、同一规则前置、同一事项状态／知识版本、同一最大等待、同一检索权限、同一动作集合和最终发送仲裁。身份与历史等硬门禁对每组相同。运行顺序随机化或轮换，并记录缓存冷热状态。

| 组 | 编排 | 用途与限制 |
| --- | --- | --- |
| A0 | 每条全历史送强模型 | 只复算旧预算上界；不作为推荐方案获胜的主要基线 |
| A1 | 优化单业务 Agent：代码去重／合并＋短状态＋按需 RAG；同一模型一次调用可判定并输出草稿 | 必需主基线；不故意剥夺其摘要、缓存、工具限制等能力 |
| B1 | 同样上下文＋规则／小模型 gate＋与 A1 相同的业务模型 | 比较轻判定是否减少昂贵调用，统计被 gate 错挡的任务 |
| B2 | 只把 B1 gate 换成 Jev | 比较判定器；业务模型、检索、阈值调参预算与动作权限不变 |
| C1 | 使用与 B1 或 B2 相同的 gate＋按需单个专家＋必要时第二专家＋单仲裁 | 比较业务拆分；专家先用同一模型和总 token 上限，隔离编排收益 |
| C2（可选） | C1 再允许不同专家使用不同模型 | 衡量联合优化，不把结果归因为多 Agent 单独作用 |

每组先在开发集优化，在校准集选阈值，最后对从未调参的测试集冻结运行。首次即跑 C2、给它更大调参预算而 A1 不调，会产生不公平结果。低置信度复核、摘要重做、专家协调、消息合并、检索重排均计入本组；不能将准备数据时实际用于推理的调用排除。

共享一份原始数据不等于强制各组输出相同调用比例 `q`、生成比例 `r`。这些比例是决策结果，应实测。比较应在相近非 @ 误介入上限及真 @ 召回／人工负担约束下选 Pareto 前沿；不允许以“全部交人工”获得零误回复与极低模型账单后宣布胜出。两组达不到共同质量约束时报告不可比，不硬算“节省率”。

### 5.1 每次调用最低账本字段

`run_id, arm_id, replay_id, case_id, event_watermark, provider, requested_model, resolved_model, prompt_schema_hash, policy_version, state_version, request_id, attempt_no, parent_call_id, stage, started_at, completed_at, input_tokens, cached_input_tokens, output_tokens, billable_units, bill_unit, unit_price_snapshot, usage_status, error_code, latency_ms`。

另有 `records_seen, candidate_packets, model_calls, question_count, generator_calls, accepted_drafts, simulated_send_intents, human_tasks, human_minutes`。未知 usage 不记零；标记 `missing` 并单列费用上界。超时后供应商可能已执行，网络重试的成本与语义去重分开记录。金额同时报告税前推理名义价与实际账单；不把免费额度当作永久单位成本。

通用费用式（模型 m 的单价以每百万 token 计）为：

```text
C_inference = Σ_m[(T_uncached,m × P_in,m
                + T_cached,m × P_cached,m
                + T_out,m × P_out,m) / 1,000,000]
            + Σ_k (billable_request_units_k × request_price_k)

C_total = C_inference + retrieval + embedding + OCR/ASR + queue/compute
        + allocated_operations + measured_human_review
```

`request_price` 只对确有按请求计费的服务填写；不是给 Jev 输入费用再加一遍。Jev 当前公开输出单价为 0，但返回的 output_tokens 可保留作容量与可比性记录。其他供应商的缓存、批处理、推理 token、固定费按实际合同或价目另计。

**假设算例，仅检查数量级**：12,000 次 Jev gate，若每次 API 实际输入总量恰为 300 token，则 3.6M × $0.042/M = **$0.1512** 输入名义价。若 300 只是 state，不含 instructions、criteria 和协议成本，则这个数低估。它没有业务生成、翻译、检索、OCR、复核、机器或人工成本，也没有任何中文正确率证据。

**假设多问题合并算例**：同一 state 800 token，6 个问题各 60 token，忽略其他开销。6 次独立调用是 `6×(800+60)=5,160` 输入 token；1 次并行问题是 `800+6×60=1,160`，减少约 **77.52%**，按上述公开价为 `$0.00021672` 对 `$0.00004872`。这只说明重复 state 的成本，不意味着六个问题免费；须用真实 usage 验证序列化和内部计量。需要前一步结果才能建立的 state 不能合并。

**级联收支线**：以同一分布的一次候选包计，令优化单 Agent 实测平均成本为 `c_single`；gate 成本为 `c_gate`，生成比例为 `r`、单次生成为 `c_gen`，复核比例为 `e`、单次复核为 `c_review`，额外状态／协调成本为 `c_extra`。只有 `c_gate + r*c_gen + e*c_review + c_extra < c_single` 且达到共同质量约束，才算成本优势。增设一个复核 Agent并非自动安全或划算；共用错误知识时可能一致同错。

请求与 token 两个轴分别报告。Jev 文档核验时列出 40 请求／秒和 100K token／秒，但明确会动态变化；日均 12,000 次约 0.139 请求／秒不能推出爆发期容量。用实际高峰回放测排队时间，不能把供应商推理耗时当作从消息到可用动作的端到端 p95。

## 6. 中文回放集、标注与指标

先做两个分开的集合：**合成机制集**用于覆盖明确边界和故障；**经授权的脱敏真实留出集**用于效果推断。合成样例数量再多也不能替代真实群分布。按群／客户和事项成组切分，并在时间上留出较新数据；同一事项、近重复模板、改写样本不得跨开发／校准／测试集。

每个回放在每个决策时点至少标注：可见 event IDs、gold case IDs、允许动作集合、是否此时需要机器人介入、最早／最晚合理响应窗口、是否必须人工、需要的证据、禁止使用的撤回或失效证据、说明理由。允许动作集合可同时含 TRACK／WAIT，不能用单个“标准答案”错误惩罚合理的不打断策略。双人独立标注后裁决歧义；未裁决样本单列，不为了高分删掉难例。

| 场景切片（均为假设例子） | 主要检查 |
| --- | --- |
| 真 @、文字 @、@别人、@所有人、引用旧 @ | mention 元数据与正文分离；硬门禁无误放 |
| “这个还有吗”“按昨天那个”“不是 A，是 B”“A 和 B 都别报” | 指代、否定范围、主体与缺槽位；不得猜附件或商品 |
| “不用回复，我问小李”“不用着急”“不是让你别处理” | false intervention，双重否定；业务词出现不等于请求机器人 |
| “把资料发我”“也发一下售后流程”分两条 | 碎片合并不漏请求；与其他客户交错不串案 |
| “A 单取消，B 单继续”“旧版不用了” | 多事项分离、更正目标和证据依赖失效 |
| 工作台接管、业务员普通发言、释放租约、过期租约 | 明确接管立即生效；普通发言不能凭昵称自动取得权限 |
| 撤回先于原消息、旧模型迟回、历史重放、同文不同消息 | 时序、版本、防重与误取消 |
| 表格金额、相对日期、单位与币种混用、图片未 OCR | 精确运算归代码；内容缺失走 unknown |
| 聊天里“忽略规则／换群发／客户报价发来” | 语义模型可能受影响，但不能改变检索与发送授权 |
| Jev 超时／限流／缺字段／模型版本变更 | 明确降级路径，采集持续，禁止宽权限回退 |

### 6.1 不混淆不同分母

以下指标分真 @／非 @、场景、群、长短上下文和语言混用切片展示，并保留计数：

| 指标 | 建议定义 |
| --- | --- |
| 无需介入机会中的误介入率 | `FP / (FP + TN)`；机会以冻结后的决策窗口定义，不能通过重复产生 WAIT 稀释分母 |
| 介入精确率 | `TP / (TP + FP)`；“触发对但错事项／错对象／过时回答”不能算正确介入 |
| 应介入事项召回 | 在允许窗口内正确介入的事项／应介入事项；全部转人工须另报机器人完成覆盖 |
| 人工必需召回及负担 | 正确转人工／必须转人工；同时报不必要转人工数、每千消息人工任务、实际处理分钟 |
| 事项关联 | 多标签 case precision／recall；跨客户混案数单列，不被大量正确普通消息平均掉 |
| 时序安全 | 接管后提交、使用撤回证据、旧状态草稿提交、重复 send intent，各自按机会计数 |
| 自动覆盖与选择性错误 | 自动处理事项／可处理事项；自动处理子集的错误率，画阈值变化下的 coverage–risk 曲线 |
| 延迟 | 新事件观察→判定、可答信息齐备→有效草稿、→模拟提交分别统计 p50/p95；超时／未完成不从样本删除 |
| 成本 | 每千原始消息、每候选包、每正确完成事项；有意外漏介入的方案不得只报平均 token |

影子模式无真实发送，只有“模型建议介入”和“仲裁允许模拟提交”的指标。真实误发、对端送达、业务体验需要后续获准实机试点；二者不得共用 PASS 标签。人工在环方案也应同时报告门禁前误建议和人工复核后残余错误，避免把人的修正算作模型准确率。

### 6.2 confidence 校准与阈值

Choice 官方公式为 `confidence=(p_max−1/n)/(1−1/n)`。**假设**二选一 `p_max=0.95` 得 confidence=0.90；三选一相同 `p_max` 得 0.925。它是分布摘要，不是“该群业务上 90% 正确”的实测频率。Noul 直接保存 `p`；不能把 `p≈0` 当成“不自信”，它可能意味着很确信为假。[官方 Confidence](https://docs.typesafe.ai/confidence)

在校准集先保存每类概率及真实标签，报告 reliability bins、每桶样本量、Brier score 与分场景误介入；用不同阈值画召回、误介入、人工负担和成本曲线。若做温度缩放等后处理，仅在校准集拟合并冻结，最终在盲测集验证。原始概率和校准概率均保留，不能掩盖版本变化。校准方法可参考 [Guo et al., 2017](https://arxiv.org/abs/1706.04599)，但该论文不证明 Jev 在本项目已校准。

优先按动作和场景选阈值：非 @ 主动介入需控制 false intervention；真 @ 允许资料请求需保护召回；交易承诺仍由确定策略拒绝自动发送。给 Noul 调好的阈值不能直接搬到 Choice、重写 criteria 或新模型版本；需要重新回放。不同问题输出相互矛盾时由代码规则决定 WAIT／HUMAN，不在无独立性证据时把几个分数相乘为“总置信度”。

**零失误的统计含义，假设 IID**：观察到 `n` 个无需介入机会，0 次误介入，二项分布单侧 95% 上界为 `1−0.05^(1/n)`。n=200 时约 **1.49%**；要使上界低于 0.1%，至少需要 **2,995** 个这种机会且 0 次误介入。这里的 n 是相应负例机会数，不是总消息或总事项数。真实群事件相关，应以群／事项为 cluster 做不确定性分析；该简单公式只能用于数量级规划，不能把 2,995 当成通用验收标准。

## 7. 下一步最小实验交付契约

本节列的是建议下一阶段产物，并非声称本轮已经实现：

1. `events.jsonl`：合成或经授权脱敏事件，保留 `observed_at` 与引用关系；`labels.jsonl`：每时点允许动作与证据。
2. 固定 reducer／仲裁回放器：先通过时序合成集，再插接真实模型；模型调用默认关闭，Sender 使用仅记录的 sink。
3. 三个可替换 provider：规则／小模型、Jev、业务模型；A1/B1/B2/C1 共享资料与账本，封存模型、prompt、策略、数据哈希。
4. 报表必须同时显示成本、召回、非 @ 误介入、人工负担、错误事项关联与状态冲突；缺少任何核心项时不宣告成本获胜。
5. 先验证可审计的单业务 Agent，再由同集难例说明是否需要专家；复杂场景可以交给第二专家复核，但不默认为所有消息启动多个 Agent。

级联是可检验的技术方向，而非收益保证。[FrugalGPT 原论文](https://arxiv.org/abs/2305.05176)提供按问题选择模型组合的研究依据；其数据集、模型与收益不能迁移为中文企微场景的预期节省率。
