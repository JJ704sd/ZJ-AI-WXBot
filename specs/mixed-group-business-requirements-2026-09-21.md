# 个微／企微混合群 Agent 业务需求与采购验收

日期：2026-09-21。依据已读取任务《拆解微企混合群代理需求》的最新需求分析；用于方案比较和试点准备，不是实机执行授权。当前能力证据见[技术可行性报告 v1.12](agent-personal-wechat-mixed-group-feasibility-report-2026-09-16.md)。

## 业务范围

首选由 Agent 接管个微账号，优先保留现有约 300 个个微／企微混合业务群；可以调整接管的个微账号。企微承载或迁群单列替代方案，明确客户配合与迁移成本。

两条流程：每日在执行窗口按群真正 @ 指定联系人索价；收到对接管账号的真实 @ 后，按批准场景及资料回复，其余交原群业务员。首期以每群每个配置执行日一次为基线，不要求追踪收齐、催收、解析价格表入库、比价、自动报价、订单确认或时效承诺。

普通文字单次受控测试是局部验收，不代表最终可以免验真实 @。初期逐条人工审批与最终批准范围内自动回复分别建设和验收。人工审批绑定该次目标和完整正文，变化即失效；自动发送按预先批准的群、对象、场景、模板／资料检查，符合策略的变量替换不需逐条重批，越界或身份未知则停止或转人工。业务需求确认不等于当前代码已开放这些动作。

## P0 功能与交付分工

| 模块 | 完整交付要求 | 供应商和我方需明确的分工 |
|---|---|---|
| 账号连接 | 在线状态、掉线告警、恢复、精确运行条件和人工共存 | 个微／企微身份、客户端／设备／服务版本、登录限制 |
| 群及成员 | 白名单、负责人、联系人、改名／重名／退群处理 | 可靠账号／群／成员标识及失效条件 |
| 定时索价 | 执行日、窗口、统一模板、按群变量和覆盖、单群／全部暂停 | 已有调度还是补建；内置与自建调度不能重复执行 |
| 入站处理 | 群、发起人、类型、被 @ 对象、新旧、去重及自身排除 | 真实接口样例、缺失字段、历史／重投／补收语义 |
| 回复策略 | 只用批准资料和同群必要上下文；场景白名单；不确定转人工 | 模板、模型、知识资料与权限边界；群消息不能扩大权限 |
| 人工待办 | 群、发起人、原消息、原因、负责人、时间、处理状态 | 通知渠道与成功依据；无负责人进统一队列 |
| 接管状态 | 接管／完成／恢复，明确单请求、事项或全群暂停 | 不可靠地识别人工回复时提供手动控制，不假装已自动识别 |
| 发送保护 | 人工审批绑定目标／正文；自动发送校验批准策略；任务账本、防重、超时核查 | 未提交、受理、unknown、接收验证分层，unknown 不盲目重发 |
| 运维与数据 | 日志、停止、告警、留存、访问、导出及删除 | 各组件责任、数据流、维护和退出安排 |

定时索价优先使用批准模板，不必每次调用模型。价格／订单／时效承诺首期转人工；文件只确认实际已看到的事实。多请求只解决一部分不能全部结案。“已转交”仅在待办和通知实际成功后使用。

## 规模与待配置参数

300 群是覆盖范围，不是并发量、账号数或模型请求数。需填写账号分布、每群 @ 人数、执行日／窗口、入站日均与峰值、上下文范围、负责人、通知渠道、回复时限、预算和留存期限。@所有人、非工作时间、撤回与更正、错过窗口的处理单列配置，不默认补发。

## 发给供应商的沟通稿

你好，我们希望由 AI Agent 接管个人微信账号，在约 300 个个微、企微成员混合的现有业务群中工作。主要做两件事：每天按计划真正 @ 各群联系人索取价格表；有人 @ 该账号时，对简单明确、批准范围内的问题回复，其余交原群业务员。可以调整个微账号，优先保留现有群。成品系统和接口服务都可以介绍，请按现成支持、需定制、不支持、尚未验证分别说明。

1. 能否用个微账号进入这类群？业务员还能同时使用手机和 PC 吗？具体运行条件是什么？
2. 可以演示两类成员分别 @ 接管账号，以及该账号分别真正 @ 两类成员吗？改名或退群后如何防止发错？
3. 若提供 API，请给出群／成员、收消息、被 @、发文本和 @ 的完整入参与响应，成功返回说明哪一阶段？
4. 定时群发能否逐群设置对象、窗口和暂停？重启如何防重？与我们自建调度如何避免冲突？
5. 简单回复、资料范围、转人工、负责人通知及暂停恢复哪些现成、哪些需我方建设？
6. 300 群建议多少账号及设备？支持怎样的发送窗口和同时入站负载？可否提供约定条件下的运行记录？
7. 断线、重投、历史补收、发送超时如何处理？结果不确定时能否查证后再补发？
8. 请分列授权／API、部署开发、设备服务器、模型、维护和扩容费用，明确更新期限、商用范围和退出方式。

此稿未发送。购买、扫码和试用密钥均不替代具体账号动作授权。

## 演示到规模验收

| 阶段 | 验证场景 | 通过依据 |
|---|---|---|
| 契约 | 个微、现有群、交付形态、版本与权益 | 文档和演示对象与拟购产品一致 |
| 单群连接 | 两类成员普通消息和双向原生 @ | 正确群／成员、可核对原始事件及接收端真实提醒；T6 另以同一条回复在企微、个微两类接收端的记录验收，发送端回显不代替收件 |
| 拒绝反例 | 纯文字 @、@别人、自身回显、历史和重复 | 不误触发，@所有人按配置 |
| 业务 | 按时索价、批准范围回复、超范围转人工 | 原群正确内容、负责人收到可处理待办、暂停恢复生效 |
| 变化与故障 | 改名、退群、重启、断线、超时、停止 | 不错发、不重复、不盲目补发，不声称未完成的通知成功 |
| 规模 | 分阶段扩大到约定群数、时长及入站量 | 有计划任务分母、成功证据、失败／跳过／unknown、漏读、重复及恢复记录 |

完成率、延迟和恢复阈值在试点前明确；单群成功不替代 300 群验收。错群、@错人、跨群泄露或越权业务承诺为阻断项。
