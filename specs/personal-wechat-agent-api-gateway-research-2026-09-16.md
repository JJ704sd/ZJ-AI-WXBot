# 个微 API 接入候选核验记录

日期：2026-09-16。范围：公开一手文档，只读调研；未注册、购买、部署、登录测试号或调用真实收发接口。

配套：[实现 spec v0.5](personal-wechat-agent-poc-v0.5.md)、[操作提示词 v0.5](personal-wechat-agent-implementation-prompt-v0.5.md)。

## 1. 结论

当前能确定的是“微信消息渠道 → 现有 Agent → 受控动作 → 微信 API”的设计方向，尚不能确定一个已在本测试号和混合群验证可用的接入后端。先实现后端无关的 WeChat Adapter 与合成闭环；选型同时核验本地 PC Hook 适配与外部/私有化 API 服务。已有兼容版本证据的本地适配符合自建优先偏好；当前尚未找到能据以批准本机 4.x 运行的证据。GeWe API 列为服务型首选核验对象，Wechaty / PadLocal 作为备选。上述顺序是待验证的工程判断，不是稳定性、费用或合规背书。

**不把历史 Gewechat Docker 方案写成默认安装步骤。** 自建业务桥接层也不等于底层微信会话和消息数据全部在本机。

## 3. 分享材料核对与 API 的两类后端

用户补充的方案摘要已通过资料核对。它提出 `Agent Server → WeChat Adapter → WCFerry/Hook → PC 微信`，并将协议 API 列为另一条路线。本轮吸收的是隔离 Adapter、稳定成员键和任务关联思想；其中的推荐星级、风险高低比较不作为工程事实，也不构成安装、注入、降级或真实发送授权。

| 分享中的关键点 | 一手核对与本轮结论 |
|---|---|
| WCFerry 支持收发和 @ | 原仓库及 Python client 有对应接口，接口形态成立；仍不等于混合群企微成员实测通过 [S10、S12] |
| 原仓库 2026-07-10 归档 | 仓库页面已确认 [S10] |
| 适配微信 3.9.12.51 | release v39.5.2 明确列出；不能映射到 4.1.13.65 [S11] |
| 可以换维护分支 | 架构可替换，但本次定向检索未找到足以证明该 Windows 4.x 场景兼容的具体分支；不等于断言不存在 |
| Hook 比协议方案稳定/风险低 | 本轮没有同账号同群对比实测，不采纳该排序为事实 |

旧架构记录本机曾为 4.1.13.65；本轮只读查询可见 Weixin 进程，但进程模块版本字段为空，未重新取得当前版本证据。安装前应读实际安装文件版本和构建标识；不得把昨日版本当作今日已核实。

WCFerry 原 Python client 的 `_send_request` 带超时重试，`send_text` 经由它调用；异常路径还可能返回空 Response。接入前必须消除写请求隐式重试并验证错误传播，不能把默认状态值当业务成功。`get_chatroom_members` 的现实现会查询 Contact 表，需改用限定群的最小元数据路径，不能因函数名称而认定读取范围天然受限。[S12]

两条后端均暴露同一领域接口：接收事件、观测账号/群/成员、提交文本及原生 @。Hook 的底层可能是本地 RPC/消息队列，服务型可能是 HTTP/Webhook；归一化后不影响 Agent。桥接层处理传输差异，禁止让 SDK 的初始化、关闭或重连隐式启动/操作客户端。

## 4. GeWe API 文档中的具体限制

- Webhook 文档要求 3 秒内响应，并描述超时可能丢弃；接收器应先持久化，再快速应答，不能同步等待模型。[S4]
- 同页称 API 发送的消息不会触发回调，手机端发送会触发。因此不能把“必须收到本人回显”设为通用送达判据。[S4]
- SaaS 回调说明要求公网可访问地址；私有化部署能否全程内网通信仍待确认，不能把 SaaS 接法直接套到本机端口。[S2、S4]
- v2 回调页列出账号、设备、消息 ID、时间、发送/接收对象等字段，并提示历史同步、重启和重试可重复投递。适配时必须固定版本并核对真实样本，不能混用 v1/v2 字段。[S5]
- 本次读取“发送文字消息”详情页两次超时，未取得可核对的原生 @请求字段；不根据旧教程填写 `ats` 等厂商字段。真实端点、鉴权和成功/失败语义留待适配记录确认。[S9]
- 当前已读页面不足以证明回调有可验证签名、稳定重放游标或写入幂等。记录为未知，不假设具备。

## 5. 真实接入前的能力记录

实施阶段应生成 gitignored 的 `provider-profile.json` 及脱敏摘要，逐项标记 `documented / observed / unsupported / unknown`。文档声明不能自动变为 `observed`。

| 必填项 | 需要的证据 |
|---|---|
| 产品和交付 | 产品名、版本、构建标识/镜像摘要、官方文档、安装来源、许可证或服务条款 |
| 后端机制 | local_hook / protocol_service / device_service；若为 Hook，固定 Windows/微信/SDK 的准确版本组合及维护来源 |
| 成本和部署 | 自建/私有化/SaaS、收费项目和期限、是否需要额外试用或付费；操作人选择的机器/网络 |
| 数据路径 | 设备、网关、桥接、回调、模型各在哪里；哪些主体会接触会话和正文；是否仍依赖外部控制面 |
| 登录 | 本人账号可独立验证、在线探针、设备会话变化、PC/手机是否被挤下线；扫码由操作人完成 |
| 群身份 | 目标混合群存在、企微/个微成员 ID 稳定且可消歧；不能按名称唯一性推定 |
| 接收 | 精确字段、原生消息 ID、消息时间、本人标志、真实 @、@所有人、引用、同步/历史事件 |
| 发送 | 文本、原生 @单人、请求与业务响应、超时/错误语义、是否支持幂等/状态查询/回显 |
| 回调 | 网络可达方式、认证/验签、重放防护、响应期限、重复与丢失行为；不能只凭 body 里的账号信任来源 |
| 运维 | 有限重连、下线事件、可停机、撤销凭据、版本变化后的重新验收方式 |

没有真实可用网关时，开发可完成 v0.5 的 A0–A1；A2–A4 必须保持“未执行”。不得通过安装未知镜像、降低回调认证要求、改回 UIA 或从其他账号借会话来补缺口。

若需要付费、第三方托管、开放公网入口或新机器部署，在完成报价、数据路径和具体部署方案后，由操作人决定；本轮访谈只确认调研范围。
