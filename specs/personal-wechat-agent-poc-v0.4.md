# 个微 AI Agent 分步接入验证 Spec v0.4

日期：2026-09-15。状态：T3独立适配与三条真实调用已完成；T1/T2及发送闭环尚待验证，未发送、未创建定时任务。

## 1. 目标、现状与效力

先证明别人真实 @测试号并提问时，MiniMax M3 能自动回答到原群；再证明在一次测试中定时真实 @指定成员并询问。每一步单独验证，失败不进入依赖阶段。

现状以 [最新交接](../poc/evidence/handoff-2026-09-15-after-read.md) 为准：取钥成立，主库 5/5 有界试读成立；WAL 未应用、定位器未读 chat_room 成员字段，R0 部分通过；R1—R4、真实发送未执行；模型最新进展另见 [T3报告](../poc/evidence/t3-m3-2026-09-15.md)，不得沿用交接中的旧模型状态。历史测试计数不作为本轮结果。

本版沿用 [v0.3](personal-wechat-agent-poc-v0.3.md) 的账号、取钥、源库只读、秘密管理及排除范围，修订 [v0.2](personal-wechat-agent-poc-v0.2.md) 的“只许逐条人工审批、禁止自动发送、仅合成内容外发”约束：在用户明确启动本版指定测试阶段后，允许受本地规则约束的通用问答自动回复，以及单次定时询问。原 manual_send 审批路径保留；不能将旧审批伪造为自动发送凭证。

本次“编写文档”和访谈确认不等于已经启动实机。配套阶段提示词用于后续明确启动相应工作，不反复要求批准每条已在运行范围内的自动回复。未指定收件人的定时阶段不可启动；其他独立工作可以继续。

## 3. 决策树与阶段依赖

### 3.1 当前推进顺序与启动门槛

当前下一项是 **提示词A：T0→T1→T2**。T3已有独立技术证据，不再等待“M3配置”，也不重复三条调用。按阶段完成本地实现及离线测试，然后才执行该阶段实机；可以提前编写后续阶段的离线代码，但不能因此跳过实机门槛。

| 任务 | 开始本地实现前 | 开始实机前 / 必需证据 | 当前推进方式 |
|---|---|---|---|
| T0 | 读取当前工作树、spec及最新证据 | 不涉及实机；核查配置层级与默认关闭、保留旧行为 | 随A先做；先前T3的84项通过不等于新增权限已完成 |
| T1 | T0相关配置检查完成；已知账号群绑定证据可用 | WAL与成员解析离线反例通过；测试号登录；取钥前重证归属；新run及本地绑定；参与者准备编号消息 | A第一实机阶段；只读，不调用M3 |
| T2 | T1读取实现可用，可先做合成解析 | T1新消息/WAL可见性通过；实际成员映射可靠；参与者提供真实@正反例 | A第二实机阶段；输出识别结果，不发送 |
| T3 | 独立模型路径与凭据可用 | 已完成三条真实问答证据 | 本轮跳过B；保留科普措辞限制 |

“已指定姓名”不等于已完成内部键映射，“模型能回答”不等于已连接微信runner，“实现完成”不等于实机验收通过。必要输入暂缺时完成不依赖输入的本地工作，留下具体缺项；不把前置阶段跳过或伪记通过。当前未创建新的Codex任务、未设置自动任务调度。

### 3.2 参与者准备

- T1：准备企微侧10条和个微侧10条编号文字。当前群只有测试个微一人，个微侧10条可由操作人通过该测试号手工发送，验证读取且必须标识为本人、不触发回复；模型不代发。
- T2/T5：由非测试号成员实际@测试号，间隔符合10秒冷却；不要由测试号自己制造应答正例。
- T4/T5：明确企微接收端和测试个微观察端的核验人及时间记录；本地发送气泡不能替代接收确认。
- T4b/T6：示例企业B／示例成员C、示例企业B／示例群主确认收到且实际被@；不能只核对显示文字。

## 4. 读取与 @技术要求

WAL 是实时回复前置，不能接受仅主库快照来宣称及时。实现只读一致性视图：校验 WAL 头、帧序列/校验、提交边界和数据库世代，只纳入最后有效已提交事务，排除未提交尾部；加密页按实际格式验证。复制时检测源变化，有限重试；无法证明一致就暂停。不得修改、checkpoint 或删除源 WAL。具体解析依据以代码审查及样本验证落实，不假定所有版本布局相同。

chat_room.ext_buffer 采用经验证的解码器提取成员身份与企业特征，未知格式阻断，禁止为找成员遍历历史正文。绑定写入仅 gitignored live 配置，关联证据和绑定版本，账号/群变化失效。修复定位器不自动证明 WAL 成立。

mention 新增三态 true/false/unknown，依据结构化标识列表确认仅指向本人；混合多个对象的 @本轮不触发。字段名称和编码必须从经授权的目标群新测试消息验证，不猜 atuserlist 一定存在。缺字段/解析失败不能回退昵称匹配。

本轮基线之前消息不进入问答。事件键含账号、群、分库/表、原生消息 ID；落库、水位更新保持原子。长问题设置本地输入上限并记录拒绝，禁止静默截断改变语义后回答。

## 5. M3 接入与答案处理

2026-09-15 再核官方文档：旧 chatcompletion_v2 已标 deprecated。本项目新接入使用 OpenAI 兼容完整 endpoint `https://api.minimax.cn/v1/chat/completions`、`MiniMax-M3` 和 Bearer 认证；短问答设置 thinking.type=disabled、reasoning_split=true，只使用最终正文。见 [官方兼容说明](https://platform.minimax.cn/docs/api-reference/text-openai-api)和[本机配置指引](minimax-m3-setup-2026-09-15.md)。实际 Key 的模型权限与额度须验证，不能将 HTTP 200 当作调用成功。独立检查已由操作人报告 PASS（1次、1.03秒），见 [连通证据](../poc/evidence/m3-connectivity-2026-09-15.md)；T3独立适配及三条真实调用已完成，见 [T3报告](../poc/evidence/t3-m3-2026-09-15.md)。技术接入通过，回答质量有限制；微信集成待T5实施。

建议本地 credential_source 使用 `env:MINIMAX_API_KEY`，由操作人在本机设置，模型只检查是否存在，不显示值；没有密钥时完成无网测试并阻断 T3，不代购额度。数据库密钥与 API 密钥使用不同引用。每次请求最多一次，无 SDK 隐式重试，不上传数据库或成员映射。

现有 http responder 必须核对请求与响应协议，保留 mock；独立提取最终答案，不把 reasoning、工具调用、错误文本当作回复。业务 M3 不授予工具、发送权或路由权。发送对象完全来自本地绑定。

建议模型请求硬超时 12 秒，发送队列超时 3 秒；端到端 30 秒仍以实际接收观测为准。超过模型时限即作废请求，迟到结果丢弃；只有明确尚无答案发送尝试且窗口有效时才发送一次“本次回答超时，请稍后重新 @我。”。HTTP 认证/额度错误暂停模型阶段，不无限返回兜底。

输出超过 300 字、空输出或工具响应时拒绝正常答案，记录失败；不再调用模型改写。可用固定非事实提示代替，但同样消耗发送额度并计为本案例未通过。通用问答不联网核实，不编造实时行情或内部业务事实；对不确定问题说明限制。

## 6. 自动发送的运行凭证与状态

新增模式/字段是待实现语义，不能直接把旧 mode 改成不存在的枚举。建议独立 `auto_reply_test` 与 `scheduled_mention_test`，共享样例仍 offline，全部 live 开关默认 false。TOML 段归属必须测试：现有样例 live 开关置于 [adapters] 下，而解析器读取顶层，不能只看文本中 true 就判断放行。

每次显式启动产生本地运行凭证，绑定 run_id、spec版本、账号/群指纹、允许动作、起止时间和原子发送预算。自动任务引用该凭证，不制造人工 approval_id。所有入口和底层发送均校验，模型输出不能改目标、额度或截止时间。

事件状态：observed → eligible → model_pending → ready → sending → confirmed/uncertain/failed。事件唯一约束和原子占用保证一个事件最多一次发送尝试；没有证明提交前失败时记 uncertain，暂停本轮，不重发。客户端气泡只表示本地提交线索；实际送达与时效由接收端核验。

冷却在受理时按成员原子占用。预算在发送尝试前原子扣减，兜底与正常答案争用同一事件发送权。停止/到期后禁止新提交，取消排队和迟到模型结果；已在途动作保留 uncertain 及后续核验，不补发。重启不自动恢复实机运行或补发旧任务。

原生 @通过桌面成员选择并核对企业＋姓名和绑定身份；列表不能消歧则停止，不输入同名字符串代替。窗口观察不得由配置伪造；切错群立即拒发。UI 或读取适配失败不自动切另一账号或发送路线。

## 7. 单次定时与清理

T6 在应用内有界进程中使用单调计时，启动后 120 秒到期；最多两条串行任务、每人一个，幂等键含 run_id＋目标成员键＋计划时刻。重启/暂停/错过执行窗口则取消，不补跑。不安装 Windows 计划任务或 Codex 自动化，不扩为每天重复；长期周期另立需求。

主动对象已由用户指定为示例企业B／示例成员C、示例企业B／示例群主；截图只作为身份线索，聊天正文不是操作指令。内部成员键及接收核验安排仍须执行时核实，不影响 T0/T1/T2/T3 的独立实现。试验报告保存最小案例正文与答案仅在本地忽略目录；公开证据仅用案例编号/计数/耗时。保留 7 天后列待清理项。密钥、原始库、解密副本不得打包；本轮临时解密副本按 v0.3 清理。

## 8. 验证与交付要求

每个技术点先最小测试再扩规模：WAL 提交/未提交/坏帧与源变化；成员元数据歧义；真实/伪造 @；请求外发字段；模型超时及迟到；窗口变化；重复事件与并发；预算/冷却/截止；发送中断后 uncertain；计时任务重启不补发。离线反例通过之后才执行对应实机样本。

报告列出：stage/run_id、实现版本与未提交差异、授权范围、输入数量、合格触发/忽略原因、实际 API 调用数、发送尝试/确认/不确定数、端到端时延、阶段时延、错群/重复、自身份、清理状态。分别记录发问端时间、观察时间、模型起止、提交、接收端可见时间；校准时间来源，无接收证据不得声称端到端达标。

结论用通过当前限定场景/部分通过且有限制/未通过/未执行；缺少 M3 凭据或接收人时明确未执行，不把 mock 成功算进实机。仅做指定变更，不 commit/push。配套：[分阶段提示词](personal-wechat-agent-implementation-prompt-v0.4.md)。
