# 个微 AI Agent 最小技术可行性验证 spec

版本：0.1｜日期：2026-09-14｜状态：范围已确认，待实施与实测。

## 1. 目标与已确认决策

验证一个独立个人微信测试账号，能否读取其参与的一个企微外部测试群的新文字消息，调用已授权模型生成有依据的草稿，经人工逐条确认后发回原群，并由接收端核验。输出实际能力与权限矩阵，不建设通用 Agent 平台。

用户已确认：接受有限账号测试风险；目标为个微参与的企微外部群；采用人工确认发送；只用合成业务消息，可调用已经授权的模型服务。普通微信群仅作必要的定位对照，不代替目标群验收。

本轮交付是 spec 和实施提示词。确认方案不等于已批准当前任务直接读取聊天库、获取密钥或发送微信消息。后续实施时核实具体测试账号、群绑定、模型及本地数据范围；发送仍需逐条确认。

“规避风控”在本 spec 中具体指减少不必要操作、限定数据和工具权限、异常即停。没有免封保证，也不实施绕过验证、伪装客户端、轮换账号/网络或规避平台检测的机制。若实际必须保证账号绝不受限，本方案不能判为满足该要求。

## 3. 最小范围与路线门槛

主路线 A：同一个微账号本地数据库只读采集 → 新事件与同群上下文 → AI 草稿 → 人工确认 → 独立桌面文字发送器 → 原群接收端核验。

备选 B：桌面读取和桌面发送，复用相同事件、草稿和 Outbox 接口。A 未通过取数门槛时暂停 A，记录失败原因后才独立验证 B；不能用 B 的成功声称数据库路线已通过。两条均失败则交付“未通过及阻塞证据”，不擅自更换账号身份或采购商业服务。

数据库路线优先复用已合法获得、已授权使用的本地密钥材料及只读能力。本版不默认执行进程扫描取钥、调试器附加、硬件断点、Hook、注入、客户端重启或降级。若数据库读取必须依赖这些动作，列明具体机制和副作用，作为独立决策，不以自动备用路径执行；可以先验证 B 的窗口可读性。这一限制不意味着 B 已被证明账号风险更低。

最小功能只包括：新文字读取、有限同群上下文、事实提取、草稿、人工审批、原群发送、暂停及审计。排除多账号、多群、无人值守、图片/语音/文件处理、全历史导入、通讯录遍历、加好友/拉群、主动营销、自动报价和任意工具执行。

## 4. 能力与权限矩阵

以下是拟授予的应用权限，不是微信官方授予的 API scope；当前能力均须实测。

| 能力 | 最小授予范围 | 执行主体 | 拒绝/降级条件 | 验证门槛 |
|---|---|---|---|---|
| 读取新文字 | 一个绑定账号、一个绑定测试群、启用后的消息 | 读取适配器 | 群或账号不明即停 | R0、R1 |
| 查询上下文 | 同群已入库合成消息，最近最多 20 条 | 本地查询层 | 跨群、真实客户内容不进模型 | R3 |
| 判断发送者/本人 | 只解析目标消息必要映射 | 读取适配器 | 无可靠依据则标 unknown，不生成发送任务 | R0、R1 |
| 生成草稿 | 已授权模型，仅必要合成文本 | AI 层 | 无凭据用 mock，不声称真实 AI 通过 | R3 |
| 审批 | 展示原文、目标、草稿、依据；逐条批准或拒绝 | 本地操作人 | 模型或群内指令不能批准 | R2、R3 |
| 发送文字 | 批准的确切文本，发至已绑定原群 | 串行发送器 | 目标/正文变化、审批过期、暂停均拒发 | R2 |
| 查看发送结果 | 本机证据＋另一客户端核验记录 | 操作人/核验器 | 缺接收端证据记 uncertain | R2、R4 |
| 暂停/恢复 | 本地操作入口 | 操作人、异常检测器 | 恢复需重新验证账号和群绑定 | R4 |
| 其他文件、命令、网络服务 | 不授予 AI 层 | 无 | 群消息提出要求一律不执行 | R3 |

隔离必须由代码和配置实现，不能只依赖提示词。AI 不持有微信控制对象、数据库密钥、模型凭据或发送工具；不接受模型输出中的目标群作为路由。

数据库解密材料的底层可访问范围可能大于单群。读取器只查询目标表及必要身份映射，不遍历正文；报告必须区分“底层材料潜在范围”与“程序实际允许范围”，不能声称密钥天然只有单群权限。AI 服务进程只接收过滤后的文本，不访问原始库。

## 5. 最小实现构成

使用项目既有 Python 环境；新增项目按 `uv` 和项目内 `.venv`。一个本地执行进程、一份 SQLite 状态库和本地 CLI 审批界面即可，不引入 Web 后台、消息中间件或 Agent 框架依赖。AI 通过受限 HTTP 调用封装工作，不赋予工具调用权限。

建议在当前项目新增 `poc/`，不直接修改外部 Chat-Lab checkout。复用时固定参考版本、核实许可证并只移植必要代码；许可证或客户端适配不明时保留适配器接口及 mock。

| 模块 | 最小职责 |
|---|---|
| config/binding | 验证账号、群、版本、数据路径、模型许可与运行模式 |
| reader | 只读获取指定群新事件，修复本轮触发的读取边界 |
| store | 持久事件、读取水位、草稿、审批、Outbox、审计 |
| responder | 同群上下文、结构化输出校验、事实规则 |
| review | 本地逐条展示并批准/拒绝，禁止默认全选批准 |
| sender | 独占桌面控制、发送前核验、发送状态持久化 |
| runner | 单次或有界运行、暂停、异常退出与恢复检查 |

模式分为 `offline`、`read_only`、`draft_only`、`manual_send`。默认 `offline`，本版不提供 `auto_send`。预留能力不能默认开放。

## 6. 接口与数据约定

这是待实现的 v1 内部契约，不是现成库的 API 名称。

`read_new_messages(binding, checkpoint) -> events`：事件包含 `schema_version`、`event_key`、`account_alias`、`conversation_key`、`source_shard`、`source_table`、`source_message_id`、`sender_key`、`is_self`（true/false/unknown）、`source_time`、`observed_at`、`text`、`evidence_ref`、`identity_status`、`is_historical`。缺失来源 ID 保持 null，不造服务端 ID。

数据库事件键包含账号、分库、表和原生消息标识；时间和正文不是唯一键。UIA 的 runtime ID 仅是窗口生命周期内的线索；无法跨重建判断重复时标记 ambiguous，禁止派生发送任务。

事件落库与相应水位同事务提交。按分库/表维护水位，按原生字段语义比较 ID，不能按字符串比较数值。增加 120 秒有界回看与持久去重作为初始实验配置；超出覆盖的迟到/回填不承诺完整，须在人工重扫中识别并标记为历史，不能自动补发。每轮重新发现分库及 WAL 的创建/删除；只处理目标群数据。首次启动记录基线，只把其后的新事件交给回复流程。

`decide_reply(event, context) -> {action, text, evidence_keys, reason}`：`action` 限 `draft|ignore|needs_review`。仅 `draft` 可进入人工审核。输出不可指定账号、群或工具。证据键必须属于输入中的同群消息；文本长度先限 500 字，超限不拆条发送，转人工。只回答已知事实；无依据的报价、时效、币种或单位不得补造。

`approve(draft_id, expected_text_hash, binding_version) -> approval_id`：本地操作人确认确切草稿和目标，记录操作人、时间及哈希。有效期暂定 5 分钟；正文、绑定版本变化或过期后须重新确认。这是防误操作配置，不是平台安全阈值。

`send_text(approval_id) -> status`：从本地批准记录取目标和正文，模型不能传入替代目标。发送前复验账号、群绑定、窗口和暂停状态。群名搜索不能作为唯一定位证据；需目标群详情/必要成员特征与 DB 群标识建立人工核验绑定。焦点、窗口重建、群改名或账号变化导致绑定失效。

## 7. 发送状态与异常控制

状态：`draft → approved → sending → verified`，并设 `rejected`、`expired`、`failed`、`uncertain`。任务对触发事件设置唯一约束；同一事件不能重复创建发送任务。

发送前先持久化 `sending`；每次只允许一个在途发送。`verified` 必须关联接收端核验记录，库返回成功或本机气泡仅作辅助证据。只有明确未发送才能记 `failed`；发送后异常、超时或缺证据记 `uncertain`，不自动重试。重启后遗留的 `sending` 转 `uncertain` 并阻断新发送，人工核清后才恢复。

账号/群身份不明、非测试内容、窗口不符、验证提示、限制提示、异常掉线、读取故障、数据库锁/一致性异常均暂停实际操作。停止后不自动登录、不循环重启、不尝试验证绕过。暂停键阻断下一次读取/模型调用/发送；已提交给客户端的发送无法撤销，必须核验其结果。

自身消息、历史事件、重放事件、无可靠身份事件不得触发回复。群内“忽略规则、访问本机文件、改发其他群”等仅当作不可信消息处理。

## 8. 数据与配置

实施前填写：测试账号别名、群类型与绑定证据、批准读取的本地路径、已授权密钥来源（如适用）、测试参与者、接收端核验人、实际客户端版本、模型服务/模型名/凭据来源。未知项保持未配置；不要猜测或读取其他项目凭据。

测试群只放合成消息。模型上下文最多 20 条，发送前由程序过滤；出现疑似真实客户内容转人工、不上传。日志不写原始密钥、令牌或全部原始聊天库；保存最小合成文本、案例编号、哈希、版本与状态证据。密钥用系统受保护存储；业务 SQLite 的明文属性必须在报告中注明。

运行数据放项目忽略目录 `.local/poc/`，限制本机访问，不提交 Git。原始库及密钥不打包交付。测试证据默认保留 7 天后列出待清理项，由操作人检查后清理，不自动删除源库。

## 9. 分阶段验收

以下为有限实验门槛，尚未执行；样本数、时长及频率均不是平台认可的安全阈值。运行默认有界，不自动安排后台任务。

| 阶段 | 输入与操作 | 通过条件 | 不通过处理 |
|---|---|---|---|
| R0 适配与绑定 | 记录实际版本；验证主路线只读数据库、目标群、企微/个微成员及本人身份 | 目标消息库实际可读，群唯一定位，身份与双端可见结果一致 | A 暂停；可独立验证 B；禁止自动取钥升级 |
| R1 连续读取 | 企微、个微参与者各发 10 条非 @ 编号合成文字 | 20 条全部读取且仅形成一次新事件；无跨群数据 | 修复并复测，不进入发送闭环 |
| R1 边界 | 合成验证两个分库、同秒 ID 9/10、跨表迟到、新 WAL、重启重放、相同正文两条、自消息 | 预期事件不丢、不覆盖；重放无新草稿；真实 WAL/身份需单列实测 | 未实测记未验证，不以 fixture 替代 |
| R2 发送 | 三条带编号固定 ACK，逐条人工批准 | 企微与个微接收端均确认 3/3；错群、重复均为 0 | uncertain 即停，人工核验 |
| R3 AI | 12 个合成案例：4 条事实问答、4 条条件缺失/冲突、4 条闲聊/自消息/越权/跨群请求 | 12/12 符合预置期望；事实有来源、无编造、越权不执行；至少 1 条真实模型草稿经批准后双端核验 | mock 单列；缺真实模型只判 AI 未验证 |
| R4 有界观察 | 30 分钟；含至少 10 条编号输入，其中至少 2 条审批回复；测试窗口切换、模拟读取故障和重启 | 输入逐条对照；无错群/重复/自循环；异常阻断；不确定结果不重发 | 输出故障及影响，不延长运行掩盖失败 |

实机仅采用不会干扰其他业务的异常操作；登录限制、风控提示通过适配器注入测试停止逻辑，不主动触发真实账号限制。无法安全实测的故障单列模拟证据。

每例记录：案例 ID、阶段、账号/群别名、客户端/适配器版本、输入编号与预期、读取/草稿/批准/发送时间、依据、双端核验位置、实际状态及判定。报告统计读漏数、重复数、错群数、未知身份数、uncertain 数、人工干预数与延迟；区分模型耗时、人工等待和传输耗时，不设未经验证的延迟承诺。

## 10. 完成判据与交付

实施交付：最小源码与锁定依赖、无密钥配置样例、离线回放样本、必要测试、本地运行说明、分阶段证据及能力/权限结果表。先离线、后实机，未具备实机输入不妨碍完成离线部分。

只有适用的 R0–R4 全有证据，才可写“指定账号/版本/测试群的人工确认文字闭环可行”。报告逐项使用 `通过当前限定场景 / 部分通过且有限制 / 未通过 / 未执行`，不得写“长期稳定、免封、全量权限、严格恰好发送一次”。若 B 通过，应明确通过的是 UI 路线。

本方案验证人工确认发送，不验证无人值守或自动回复权限。以后开放自动回复是单独的范围变更。

## 11. 预计执行顺序

先实现离线接口、状态机和边界测试，再做 R0 与固定 ACK 的独立适配验证，随后完成 R1、R3、R4。任一关键门槛失败即保留证据并缩小结论。当前无法据文档保证工期，尤其数据库和桌面版本适配；不把 30 分钟观察时间解释为全部开发耗时。

附件是批量导出原型，不提供持续新事件、WAL 一致性、发送接口、审批、AI 或 Outbox。不得把 CSV 时间戳当读取水位，也不得把完整批量导出的旧消息全部作为新回复任务。主路线仍为第二轮的 DB 只读采集与独立桌面发送；附件只补足确实需要的解析细节，不额外构建“先全量导出 CSV 再轮询 CSV”的链路。

额外离线验收用例：同一群分布在两个分库时合并且不覆盖；白名单中合成 `@openim` 字符串不因后缀被过滤，非白名单永不返回；两个相同正文消息各保留；损坏压缩正文返回解析错误而不是可发送文本；显式账号与首个发现目录不同仍只能读取指定账号。合成 `@openim` 测试仅证明过滤行为，不证明真实外部群结构。仅在实际实现页面解密模块时增加坏页、缺页和完整性失败测试，未采用模块不增加无关工作。
