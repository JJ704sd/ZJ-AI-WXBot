# R0 进程归属恢复与重跑方案

日期：2026-09-15。依据：[R0 失败记录](../poc/evidence/r0-v03-live.md)、[spec v0.3](personal-wechat-agent-poc-v0.3.md)及 v0.2。本文为执行方案，不代表已切换账号或已重跑。

## 1. 结论与完成判据

旧运行 `r0-20260915-6126326b` 停在 G-KEY：测试号库无持有进程，排除号库有一个持有进程。未扫描内存、未取得密钥、未开库；R0 未通过，R1—R4 未执行。该记录是上次快照，不能当作当前进程状态。

恢复目标：操作人登录指定测试号后，重新证明目标库由唯一 Weixin 候选进程持有，候选进程不持有已排除账号库，再按 v0.3 完成 R0。权限已经存在，不需要重新要求操作人提供密钥。归属通过仅允许进入取钥，不代表取钥、开库或 R0 通过。

## 2. 操作人准备

1. 在个人微信客户端正常退出当前账号并登录测试账号。扫码或登录确认由操作人完成；不要向助手发送密码、二维码或令牌。测试数据目录为 `wxid_example_account_dir`，目录后缀不是可直接输入的登录凭据。
2. 核对所登录的确为该测试号，并确认个微侧能找到“示例混合群”。可查看群详情核对成员及企业特征，无须发送消息或导出聊天。“示例本人”仍须核实，不按昵称猜测身份。
3. 保持客户端登录。若仍无目标库持有记录，可由操作人在正常界面打开目标群一次，再做一次只读复核；不要发送测试文字，不修改或删除库/WAL。
4. 告知助手“测试号已登录，请按重跑提示词执行”。此陈述是准备完成通知，模型仍需验证进程归属。

v0.3 §3 对操作模型保留“切换账号、重启或降级客户端”的禁令，因此本方案把登录切换交给操作人。它不阻止操作人正常准备客户端，也不要求再次审批已授权的取钥和开库。本文不新增模型控制登录或重启权限。

## 3. 模型可先完成的工作

读取实际配置、入口和最近证据，保留未提交改动。核对 `r0-run` 的真实行为、新 run_id 生成方式、独立输出路径及脱敏输出；不要重做已经落地的门槛拆分。

检查 `process_own.py` 的查询错误处理：当前 `resolve_owned_weixin_pid` 获取 `excluded_error` 后未据此拒绝，且目标查询错误只在无 owned PID 时阻断。执行前应使任一相关归属查询失败都保持“未知并阻断”，不得把失败当作空集合。调用端不得因排除号查询失败而省略排除路径。针对该缺口增量修复，并用合成反例验证；这是后续执行任务的改动要求，本次文档没有修复代码。

验证强度限于相关归属与 v0.3 门槛回归；涉及公共门槛或其他实现变化时再跑项目必要检查。旧记录的 70 collected、1 skipped 不作为本轮测试结果。

## 4. 新一轮归属门槛

| 检查 | 通过条件 | 不满足时 |
|---|---|---|
| 目标路径 | 最终解析路径属于测试账号，非越界链接 | 停止 |
| 查询结果 | 目标与排除路径的持有查询均成功 | 查询失败记未知，不扫描内存 |
| 候选进程 | 目标库持有者与 Weixin PID 的交集恰好一个 | 0 个记账号未活跃；多个记归属不唯一 |
| 排除交集 | 候选 PID 与排除号持有者无交集 | 有交集则停止 |
| 新鲜度 | 取钥前重新核对 PID、进程身份及账号文件关联 | 进程退出/重建/登录变化则旧证据失效 |
| 配置 | read_only；三个读取/定位/取钥开关为 true；发送为 false | 修正本地配置或报告具体阻塞 |

`holder_pid_count` 不是唯一通过条件；必须结合 Weixin 候选交集判断。`excluded_holder_count>0` 也不自动失败：排除号若仅由另一个进程持有，不等于候选进程混用账号。不要为了使计数归零而强杀其他进程。只检查排除号已知路径的占用元数据，不打开其数据库，不扫描其进程内存。

归属预检与取钥之间必须尽量缩短间隔；进程身份变化时重新检查，不能只复用一个可能被系统重复分配的 PID。平台查询权限不足时记录具体错误，不关闭安全软件或移除守卫。

## 5. 重跑顺序及停点

1. 自行生成新的 run_id，关联旧失败编号和原授权；使用独立运行输出，不覆盖旧证据、不复用旧基线或密钥。
2. 完成上述代码检查、必要修复及测试。确认实际 CLI 与配置兼容，再执行已实现的 `r0-run`；不要用一般 `run` 代替 R0。
3. 归属通过后按 v0.3 自主取钥，密钥只在受控本地工具内传递，不输出值。
4. 只读开库并核实完整性、WAL 一致性；元数据唯一定位目标群、核实本人、建立 ID/时间基线。任一阶段失败就停止依赖步骤，保留已完成证据。
5. 清理本 run 的临时密钥引用、句柄与解密副本，保存脱敏报告。R0 完成即停，不进入 R1—R4，不发送、不调用外部业务模型、不安排后台任务、不 commit/push。

## 6. 分支处理与交付

| 结果 | 下一步 |
|---|---|
| 测试号仍无候选 PID | 报告当前只读证据，请操作人核对登录账号；不重复扫描所有 PID |
| 候选同时持有排除号 | 停止取钥，由操作人处理客户端会话；不借用排除号密钥 |
| 查询失败或进程不稳定 | 修复可定位的查询问题或报告平台阻塞，不能判为无冲突 |
| 归属通过但无有效密钥 | 区分获取与格式验证失败，不扩大账号/进程范围 |
| 开库成功但 WAL/群/本人缺证 | 仅记部分通过且有限制，后续不派发任务 |
| 所有 R0 条件满足 | 记录通过当前限定场景；R1—R4 仍未执行 |
